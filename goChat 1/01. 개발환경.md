# 개발·실행 환경

이 프로젝트는 역할을 두 장비로 나누어 실행했다.

```text
MacBook (로컬)
└── k6 부하 테스트 실행

Mini PC
└── Proxmox VE 9
    └── Ubuntu Server 24.04 LTS VM
        └── Go · Docker · Minikube · Kubernetes 구성요소 실행
```

MacBook은 테스트 요청을 만드는 Client이고, 채팅 서버와 인프라는 Mini PC의 Ubuntu VM에서 실행한다.

---

## 로컬 MacBook

### 역할

- k6 WebSocket Smoke Test와 동시 연결 부하 테스트 실행
- Tailscale을 통해 Mini PC의 테스트 진입점에 접속

MacBook에서 PostgreSQL, Redis, Docker, Minikube, Chat Pod는 실행하지 않는다.

### Load Test

- 도구: k6
- 대상: Mini PC Ubuntu VM에서 실행 중인 Go 채팅 서버 또는 Kubernetes Ingress
- 접속: 테스트 단계에 따라 Tailscale, `kubectl port-forward`, `socat → Ingress NodePort` 경로 사용

---

## Mini PC와 가상화 환경

### 물리 장비

- 장비: Mini PC
- CPU: AMD Ryzen 9 6900HX (8C / 16T)
- 메모리: 20GB
- 스토리지: SSD (사용 가능 공간 900GB 이상)

### Hypervisor

- Proxmox VE 9

Mini PC에는 Proxmox를 설치하고, 실제 프로젝트 실행 환경은 그 위의 Ubuntu VM에 구성했다.

---

## Ubuntu Virtual Machine

### Operating System

- Ubuntu Server 24.04 LTS

### VM Specification

- vCPU: 8
- 메모리: 12GB
- 디스크: 100GB
- BIOS: OVMF (UEFI)
- Machine: q35
- SCSI Controller: VirtIO SCSI Single
- Network: VirtIO (`vmbr0`)

### Ubuntu VM에서 실행한 구성요소

- Go WebSocket 채팅 서버
- PostgreSQL
- Redis
- Docker
- Minikube와 Kubernetes 자원
- NGINX Ingress Controller
- Prometheus, Grafana
- ArgoCD
- GitHub Actions가 만든 GHCR 이미지를 받는 Kubernetes 배포 환경

---

## 접속과 개발 도구

- VS Code
- Remote - SSH
- Tailscale
- Git / GitHub

Tailscale은 MacBook과 Ubuntu VM 사이의 사설 접속 경로로 사용했다. 대량 k6 테스트에서는 MacBook에서 Minikube 내부 IP에 직접 접근하기 어려워 Ubuntu VM의 `socat`이 Tailscale 주소와 Ingress NodePort를 연결했다.
