# Docker Compose 구성

## 목표

PostgreSQL, DB Migration, Go WebSocket 서버를 하나의 명령으로 순서에 맞게 실행한다.

```bash
docker compose --env-file app/.env -f docker/compose.yml up -d --build
```

전체 실행 순서

```text
postgres 실행
↓
PostgreSQL이 healthy 상태가 될 때까지 대기
↓
migrate up 실행
↓
Migration 성공
↓
app 실행
```

---

## 전체 서비스 구조

```text
Docker Compose
├── postgres
│   └── postgres:17 이미지
│
├── migrate
│   └── chat-app:local 이미지에서 migrate up 실행
│
└── app
    └── chat-app:local 이미지에서 server 실행
```

서비스는 3개지만 사용하는 이미지 종류는 2개다.

```text
postgres:17
chat-app:local
```

`migrate`와 `app`은 같은 `chat-app:local` 이미지를 사용하지만 실행 명령이 다르다.

---

## 공통 이미지 설정

```yaml
x-chat-image: &chat-image
  image: chat-app:local
  build:
    context: ../app
    dockerfile: ../docker/Dockerfile
```

`x-chat-image`는 `migrate`와 `app`에서 반복해서 사용할 이미지 설정이다.

```text
context: ../app
```

Docker가 이미지 빌드에 사용할 파일 범위를 `app` 폴더로 제한한다.

```text
dockerfile: ../docker/Dockerfile
```

실제 이미지 제작 방법은 `docker/Dockerfile`에서 읽는다.

YAML의 `&chat-image`는 설정에 이름을 붙이고, `*chat-image`는 해당 설정을 재사용한다는 뜻이다.

---

## 공통 환경변수 설정

```yaml
x-chat-environment: &chat-environment
  env_file:
    - ../app/.env
  environment:
    DB_HOST: postgres
    MIGRATIONS_SOURCE_URL: file://migrations
```

Go 애플리케이션과 Migration이 `app/.env`를 함께 사용한다.

Docker 안에서는 다음 설정이 중요하다.

```env
DB_HOST=postgres
```

Go 서버를 Ubuntu 호스트에서 직접 실행할 때는 PostgreSQL에 `localhost`로 접근했다.

```text
Ubuntu Go Server
→ localhost:5432
→ PostgreSQL 컨테이너
```

Go 서버도 컨테이너가 되면 컨테이너 내부의 `localhost`는 자기 자신을 의미한다.

따라서 Compose 서비스 이름을 주소로 사용한다.

```text
chat-app 컨테이너
→ postgres:5432
→ chat-postgres 컨테이너
```

Compose가 같은 네트워크에 있는 서비스 이름을 자동으로 주소로 변환해준다.

## PostgreSQL 서비스

```yaml
postgres:
  image: postgres:17
  container_name: chat-postgres
  restart: unless-stopped
  environment:
    POSTGRES_USER: ${DB_USER:-postgres}
    POSTGRES_PASSWORD: ${DB_PASSWORD:?DB_PASSWORD is required}
    POSTGRES_DB: ${DB_NAME:-chat}
  volumes:
    - postgres-data:/var/lib/postgresql/data
```

PostgreSQL 17 공식 이미지를 사용한다.

```text
POSTGRES_USER
→ 최초 사용자 생성

POSTGRES_PASSWORD
→ 최초 사용자 비밀번호

POSTGRES_DB
→ chat 데이터베이스 생성
```

`DB_PASSWORD`는 저장소에 기록하지 않고 `app/.env`에서 읽는다. Compose 실행 시 다음처럼 환경변수 파일을 지정한다.

```bash
docker compose --env-file app/.env -f docker/compose.yml up -d
```

PostgreSQL의 `5432` 포트는 Ubuntu 호스트에 공개하지 않는다. Go 서버와 Migration은 Compose 내부 네트워크의 `postgres:5432`로 접속하므로 외부 포트 연결이 필요하지 않다.

Volume 설정

```text
postgres-data
→ /var/lib/postgresql/data
```

컨테이너를 삭제해도 Volume이 남아 있으면 채팅 데이터는 유지된다.

## PostgreSQL Health Check

```yaml
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
  interval: 5s
  timeout: 5s
  retries: 10
```

컨테이너가 실행됐다는 사실만으로 PostgreSQL이 바로 요청을 처리할 준비가 된 것은 아니다.

`pg_isready`로 실제 DB 준비 상태를 확인한다.

```text
starting
↓
pg_isready 성공
↓
healthy
```

Migration은 PostgreSQL이 `healthy`가 된 뒤 실행된다.

## Migration 서비스

```yaml
migrate:
  <<: [*chat-image, *chat-environment]
  container_name: chat-migrate
  command: ["migrate", "up"]
  restart: "no"
  depends_on:
    postgres:
      condition: service_healthy
```

`chat-app:local` 이미지에 들어 있는 `migrate` 실행 파일을 사용한다.

실제 실행 명령

```text
migrate up
```

`depends_on` 조건 때문에 PostgreSQL이 준비된 뒤 실행된다.

Migration은 작업을 마치면 종료되는 일회성 컨테이너다.

```text
chat-migrate Exited (0)
```

`Exited (0)`은 오류가 아니라 정상 완료를 의미한다.

이미 최신 DB 버전이면 `no migration changes`를 출력하고 정상 종료한다.

## Go 채팅 서버 서비스

```yaml
app:
  <<: [*chat-image, *chat-environment]
  container_name: chat-app
  command: ["server"]
  restart: unless-stopped
  ports:
    - "8080:8080"
  depends_on:
    migrate:
      condition: service_completed_successfully
```

같은 `chat-app:local` 이미지에서 `server` 실행 파일을 실행한다.

```text
Ubuntu 8080
→ chat-app 컨테이너 8080
```

Migration이 성공적으로 끝나야 Go 서버가 실행된다.

```text
Migration 실패
→ app 시작하지 않음

Migration 성공
→ app 시작
```

---

## Go 서버 Health Check

```yaml
healthcheck:
  test: ["CMD", "wget", "--quiet", "--tries=1", "--spider", "http://localhost:8080/health/live"]
```

Go 서버 컨테이너 내부에서 다음 주소를 확인한다.

```text
http://localhost:8080/health/live
```

정상 응답을 받으면 컨테이너가 `healthy` 상태가 된다.

## Volume 선언

```yaml
volumes:
  postgres-data:
```

Docker가 관리할 `postgres-data` Volume을 선언한다.

```bash
docker compose --env-file app/.env -f docker/compose.yml down
```

컨테이너만 종료하고 Volume은 유지한다.

```bash
docker compose --env-file app/.env -f docker/compose.yml down -v
```

Volume까지 삭제하므로 PostgreSQL 데이터도 모두 삭제된다.

## 실행 및 확인

이미지 빌드와 전체 실행

```bash
docker compose --env-file app/.env -f docker/compose.yml up -d --build
```

상태 확인

```bash
docker compose --env-file app/.env -f docker/compose.yml ps -a
```

정상 결과

```text
chat-postgres   Up (healthy)
chat-migrate    Exited (0)
chat-app        Up (healthy)
```

로그 확인

```bash
docker compose --env-file app/.env -f docker/compose.yml logs migrate
docker compose --env-file app/.env -f docker/compose.yml logs app
```
