# Go 채팅 서버 Docker 이미지

## 목표

Ubuntu 호스트에서 `go run`으로 실행하던 Go 채팅 서버를 Docker 이미지로 만들고 컨테이너에서 실행한다.

변경 전

```text
Go 채팅 서버
→ Ubuntu 호스트에서 go run ./cmd/server

PostgreSQL
→ Docker 컨테이너
```

변경 후

```text
Go 채팅 서버
→ chat-app:local 이미지의 컨테이너

PostgreSQL
→ postgres:17 이미지의 컨테이너
```

---

## 이미지와 컨테이너 차이

### 이미지

프로그램 실행에 필요한 파일과 설정을 묶은 읽기 전용 설계도다.

```text
chat-app:local 이미지
├── server 실행 파일
├── migrate 실행 파일
└── migrations SQL 파일
```

### 컨테이너

이미지를 실제로 실행한 프로세스다.

```text
chat-app:local 이미지
├── chat-migrate 컨테이너
└── chat-app 컨테이너
```

같은 이미지를 사용하더라도 실행 명령에 따라 서로 다른 역할을 수행할 수 있다.

---

## Dockerfile 전체 구조

```dockerfile
# syntax=docker/dockerfile:1

FROM golang:1.25-alpine3.24 AS builder

WORKDIR /src

COPY go.mod go.sum ./
RUN go mod download

COPY . .

RUN CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags="-s -w" -o /out/server ./cmd/server
RUN CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags="-s -w" -o /out/migrate ./cmd/migrate

FROM alpine:3.24

RUN apk add --no-cache ca-certificates tzdata \
    && addgroup -S app \
    && adduser -S -G app app

WORKDIR /app

COPY --from=builder /out/server /usr/local/bin/server
COPY --from=builder /out/migrate /usr/local/bin/migrate
COPY --chown=app:app migrations ./migrations

USER app

EXPOSE 8080

STOPSIGNAL SIGTERM

CMD ["server"]
```

---

## Multi-stage Build

Dockerfile은 두 단계로 구성된다.

```text
1단계 builder
→ Go 코드 컴파일

2단계 runtime
→ 컴파일된 실행 파일만 포함
```

Go 컴파일러와 소스 코드를 최종 이미지에 넣지 않기 때문에 이미지 크기와 공격 가능 영역을 줄일 수 있다.

---

## Builder 단계

```dockerfile
FROM golang:1.25-alpine3.24 AS builder
```

Go 1.25와 Alpine Linux가 포함된 이미지를 빌드 전용으로 사용한다.

```dockerfile
WORKDIR /src
```

이후 명령을 실행할 작업 디렉터리를 `/src`로 지정한다.

```dockerfile
COPY go.mod go.sum ./
RUN go mod download
```

의존성 정보만 먼저 복사하고 다운로드한다.

Go 소스 코드가 변경돼도 `go.mod`, `go.sum`이 같다면 Docker 빌드 캐시를 재사용할 수 있다.

```dockerfile
COPY . .
```

`app` 빌드 Context의 Go 소스 코드와 Migration 파일을 복사한다.

---

## Go 실행 파일 빌드

```dockerfile
RUN CGO_ENABLED=0 GOOS=linux go build \
    -trimpath \
    -ldflags="-s -w" \
    -o /out/server \
    ./cmd/server
```

Go 채팅 서버를 Linux 실행 파일로 컴파일한다.

```text
CGO_ENABLED=0
→ C 라이브러리 의존성 없이 정적 실행 파일 생성

GOOS=linux
→ Linux 컨테이너용으로 빌드

-trimpath
→ 빌드 머신의 로컬 경로 제거

-ldflags="-s -w"
→ 디버그 심볼을 제거해 실행 파일 크기 감소

-o /out/server
→ 결과 파일 이름과 위치 지정
```

Migration 실행 파일도 같은 방식으로 만든다.

```dockerfile
RUN CGO_ENABLED=0 GOOS=linux go build \
    -trimpath \
    -ldflags="-s -w" \
    -o /out/migrate \
    ./cmd/migrate
```

---

## Runtime 단계

```dockerfile
FROM alpine:3.24
```

최종 실행 이미지는 작은 Alpine Linux만 사용한다.

Builder 단계의 Go 컴파일러와 소스 코드는 최종 이미지에 들어가지 않는다.

```dockerfile
RUN apk add --no-cache ca-certificates tzdata
```

HTTPS 인증서와 시간대 데이터를 설치한다.

```dockerfile
addgroup -S app
adduser -S -G app app
```

컨테이너를 root가 아닌 `app` 사용자로 실행하기 위한 계정과 그룹을 만든다.

---

## 실행 파일과 Migration 복사

```dockerfile
COPY --from=builder /out/server /usr/local/bin/server
COPY --from=builder /out/migrate /usr/local/bin/migrate
COPY --chown=app:app migrations ./migrations
```

Builder 단계에서 만든 두 실행 파일과 SQL Migration 파일만 최종 이미지에 복사한다.

```text
/usr/local/bin/server
/usr/local/bin/migrate
/app/migrations/*.sql
```

---

## 비 root 사용자 실행

```dockerfile
USER app
```

이후 컨테이너 프로세스는 root가 아닌 `app` 사용자 권한으로 실행된다.

컨테이너가 침해되더라도 root 권한 사용을 제한하기 위한 설정이다.

---

## 포트와 종료 신호

```dockerfile
EXPOSE 8080
```

Go 서버가 8080 포트를 사용한다는 정보를 이미지에 기록한다.

`EXPOSE`만으로 Ubuntu 포트가 열리지는 않는다. 실제 연결은 Compose의 다음 설정이 담당한다.

```yaml
ports:
  - "8080:8080"
```

```dockerfile
STOPSIGNAL SIGTERM
```

컨테이너 종료 시 Go 서버에 `SIGTERM`을 전달한다.

Go 서버는 이 신호를 받아 HTTP 서버, WebSocket 연결, DB 연결을 순서대로 정리한다.

---

## 기본 실행 명령

```dockerfile
CMD ["server"]
```

별도 명령을 지정하지 않고 이미지를 실행하면 채팅 서버가 시작된다.

```text
chat-app 컨테이너
→ server 실행
```

Compose의 Migration 서비스는 기본 명령을 덮어쓴다.

```yaml
command: ["migrate", "up"]
```

```text
chat-migrate 컨테이너
→ migrate up 실행
```

```text
.env
.DS_Store
bin/
coverage.out

```

Docker 이미지 빌드에 필요 없는 파일을 Build Context에서 제외한다.

특히 실제 DB 비밀번호가 포함된 `.env`가 이미지에 들어가지 않도록 제외한다.

## 이미지 빌드

이미지만 빌드

```bash
docker compose --env-file app/.env -f docker/compose.yml build
```

이미지를 빌드하고 컨테이너까지 실행

```bash
docker compose --env-file app/.env -f docker/compose.yml up -d --build
```

생성된 이미지 확인

```bash
docker image ls
```

결과

```text
chat-app   local
postgres   17
```

이 이미지는 현재 Ubuntu의 로컬 Docker에만 존재한다.

Docker Hub나 GitHub Container Registry에는 자동으로 업로드되지 않는다.

```bash

```

정상 결과


```bash

```

```text

```

## 정리

```text
Go 소스 코드
↓
Dockerfile Multi-stage Build
↓
server + migrate 실행 파일 생성
↓
chat-app:local 이미지 생성
↓
Compose가 migrate와 app 컨테이너로 실행
```

현재 단계에서는 Ubuntu 로컬에 이미지를 만들었다.

이후 GitHub Actions 단계에서 이미지 빌드와 Container Registry Push를 자동화한다.
