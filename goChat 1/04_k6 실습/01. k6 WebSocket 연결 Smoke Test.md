# k6 WebSocket 연결 Smoke Test

## 실습 목표

Mac에서 k6 가상 사용자 한 명을 실행하여 Ubuntu의 Go WebSocket 채팅 서버에 정상적으로 연결할 수 있는지 확인한다.

이번 실습은 서버에 큰 부하를 주는 테스트가 아니다. 실제 부하 테스트 전에 가장 작은 단위의 기능이 동작하는지 확인하는 Smoke Test다.

```text
Mac
└── k6 가상 사용자 1명
        ↓ WebSocket 연결
Ubuntu 미니 PC
└── Go 채팅 서버
```

---

## k6와 VU

k6는 실제 사용자 대신 가상 사용자를 만들어 서버에 요청을 보내는 부하 테스트 도구다.

`VU`는 `Virtual User`의 약자로 가상 사용자를 의미한다.

이번 테스트에서는 다음과 같이 생각할 수 있다.

```text
VU 1명
= WebSocket 연결 1개
```

프로젝트 루트에 `loadtest` 폴더를 만들고 첫 번째 테스트 파일을 생성하였다.

```bash
mkdir -p loadtest
touch loadtest/websocket-smoke.js
```

```text
go-devops/
├── app/

│   └── websocket-smoke.js

```

`mkdir -p`의 `-p`는 폴더가 없으면 만들고, 이미 존재하면 오류 없이 넘어가도록 하는 옵션이다.

## WebSocket 연결 테스트 코드

```javascript
import { WebSocket } from 'k6/websockets';

const wsURL = __ENV.WS_URL || 'ws://localhost:8080/ws';

export default function () {
  const socket = new WebSocket(wsURL);

  socket.addEventListener('open', () => {
    console.log('WebSocket connected');
    socket.close();
  });
}
```

### WebSocket 모듈 가져오기

```javascript
import { WebSocket } from 'k6/websockets';
```

k6가 제공하는 WebSocket 기능을 가져온다.

### 서버 주소 설정

```javascript
const wsURL = __ENV.WS_URL || 'ws://localhost:8080/ws';
```

- `__ENV.WS_URL`: k6 실행 명령에서 전달받은 환경변수
- `||`: 앞의 값이 없으면 뒤의 기본값을 사용
- `ws://localhost:8080/ws`: 별도 주소를 전달하지 않았을 때 사용할 기본 주소

서버 주소를 코드에 고정하지 않았기 때문에 테스트 환경이 바뀌어도 파일을 수정할 필요가 없다.

### 가상 사용자 실행 함수

```javascript
export default function () {
```

k6 가상 사용자가 실행할 시작 함수다. 이 함수가 한 번 실행되는 것을 `Iteration`이라고 한다.

### WebSocket 연결 생성

```javascript
const socket = new WebSocket(wsURL);
```

`wsURL` 주소로 새로운 WebSocket 연결을 시도한다.

### 연결 성공 이벤트

```javascript
socket.addEventListener('open', () => {
  console.log('WebSocket connected');
  socket.close();
});
```

WebSocket 연결이 성공하면 `open` 이벤트가 발생한다. 성공 로그를 출력한 뒤 이번 테스트에서는 연결 여부만 확인하므로 바로 연결을 종료한다.

## 테스트 실행

프로젝트 루트에서 실행할 경우:

```bash
k6 run \
  -e WS_URL=ws://100.126.215.15:8080/ws \
  loadtest/websocket-smoke.js
```

이미 `loadtest` 폴더 안에 있다면 파일 이름만 지정한다.

```bash
k6 run \
  -e WS_URL=ws://100.126.215.15:8080/ws \
  websocket-smoke.js
```

명령 구성:

| 명령 | 의미 |
|---|---|
| `k6 run` | k6 테스트 실행 |
| `-e` | 테스트에 환경변수 전달 |
| `WS_URL=...` | 접속할 WebSocket 서버 주소 |
| `websocket-smoke.js` | 실행할 테스트 파일 |

### 실행 정보

```text
execution: local
script: websocket-smoke.js
output: -
```

| 영어 | 한국어 의미 | 현재 결과 |
|---|---|---|
| `execution` | 실행 방식 | Mac에서 로컬 실행 |
| `script` | 실행한 테스트 파일 | `websocket-smoke.js` |
| `output` | 외부 결과 저장 위치 | 지정하지 않고 터미널에 출력 |

### Scenario

```text
1 scenario, 1 max VUs
1 iterations for each of 1 VUs
```

| 영어 | 한국어 의미 |
|---|---|
| `Scenario` | 테스트 실행 계획 |
| `VU` | Virtual User, 가상 사용자 |
| `Iteration` | 테스트 함수 한 번 실행 |
| `Max Duration` | 테스트가 끝나지 않을 때 기다릴 최대 시간 |
| `Graceful Stop` | 진행 중인 작업이 정상 종료될 수 있도록 주는 추가 시간 |

이번에는 가상 사용자 한 명이 테스트 함수를 한 번 실행하였다.

`10m30s max duration`은 실제로 10분 30초 동안 실행했다는 뜻이 아니다. 테스트가 끝나지 않는 상황을 막기 위한 최대 제한 시간이며 실제 테스트는 1초보다 짧게 끝났다.

### 연결 성공 로그

```text
INFO[0000] WebSocket connected source=console
```

- `INFO`: 정보 수준 로그
- `[0000]`: 테스트 시작 후 0초에 발생
- `source=console`: `console.log()`에서 출력

WebSocket 연결이 정상적으로 열려 `open` 이벤트가 실행되었다는 뜻이다.

## Execution 결과 해석

```text
iteration_duration: avg=23.49ms
iterations: 1
```

### iteration_duration

`Iteration Duration`은 가상 사용자의 테스트 함수가 시작해서 끝날 때까지 걸린 시간이다.

```text
23.49ms ≈ 0.023초
```

### iterations

`Iterations`는 테스트 함수가 완료된 횟수다. 이번에는 한 번 실행하여 결과가 `1`이다.

옆의 `42.265427/s`는 짧은 실행 시간을 초당 횟수로 환산한 값이다. 서버가 초당 42명의 사용자를 처리할 수 있다는 의미가 아니다. 측정 표본이 한 개뿐이므로 서버 성능 판단에 사용할 수 없다.

### 통계 용어

| 영어 | 원래 단어 | 한국어 의미 |
|---|---|---|
| `avg` | Average | 평균 |
| `min` | Minimum | 최솟값 |
| `med` | Median | 중앙값 |
| `max` | Maximum | 최댓값 |
| `p(90)` | 90th Percentile | 전체 결과의 90%가 이 값 이하 |
| `p(95)` | 95th Percentile | 전체 결과의 95%가 이 값 이하 |

현재는 한 번만 측정했기 때문에 평균, 최소, 중앙값, 최대, p90, p95가 모두 같은 값이다.

## WebSocket 결과 해석

### ws_connecting

```text
ws_connecting: avg=15.88ms
```

`WebSocket Connecting`은 Mac에서 Ubuntu 서버와 WebSocket 연결을 맺는 데 걸린 시간이다.

```text
Mac 연결 요청
→ Ubuntu 서버 도착
→ HTTP Upgrade 처리
→ WebSocket 연결 성공
```

이번 연결에는 약 15.88ms, 즉 약 0.016초가 걸렸다.

### ws_msgs_sent

```text
ws_msgs_sent: 1
```

`WebSocket Messages Sent`는 k6가 WebSocket을 통해 보낸 프레임 수다.

현재 코드에는 `socket.send()`가 없으므로 사용자 채팅 메시지를 한 개 보냈다는 의미가 아니다. 연결 종료 과정의 WebSocket 제어 프레임이 집계된 것으로 이해한다.

### ws_session_duration

```text
ws_session_duration: avg=22.99ms
```

`WebSocket Session Duration`은 WebSocket 연결이 열린 뒤 닫힐 때까지 유지된 시간이다.

현재 코드는 연결 직후 `socket.close()`를 실행하므로 약 22.99ms로 짧게 측정되는 것이 정상이다.

### ws_sessions

```text
ws_sessions: 1
```

`WebSocket Sessions`는 생성한 WebSocket 연결 수다. 이번에는 가상 사용자 한 명이 연결 한 개를 생성했다.

이번 테스트를 통해 다음 내용을 확인하였다.

> Mac에서 실행한 k6 가상 사용자 한 명이 Tailscale을 통해 Ubuntu의 Go WebSocket 서버에 정상적으로 연결하고 종료할 수 있다.

아직 채팅 기능이나 서버의 최대 성능을 측정한 것은 아니다.
