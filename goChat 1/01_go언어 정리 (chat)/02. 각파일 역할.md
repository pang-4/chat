현재 프로젝트는 실행 진입점, 애플리케이션 조립, 채팅 규칙, 외부 연동을 분리한 WebSocket 채팅 서버다. PostgreSQL은 메시지를 저장하고, Redis Pub/Sub는 여러 서버 인스턴스 사이에 메시지를 전달한다.

```text
cmd/server ─┐
            ├─> application ─> config / database / messaging / chat / server
cmd/migrate ┘
```

---

# 실행 파일과 Migration

## `cmd/server/main.go`

채팅 서버의 실행 진입점이다.

- JSON 형식의 `slog` Logger를 만든다.
- `application.Run()`을 호출한다.
- 실행 중 복구할 수 없는 오류가 나면 오류를 기록하고 종료한다.

세부 설정이나 연결 생성은 이 파일에서 하지 않는다.

---

## `cmd/migrate/main.go`

데이터베이스 스키마를 별도로 변경하는 명령의 진입점이다.

- 설정을 읽고 PostgreSQL 연결 URL과 migration 파일 경로를 만든다.
- `golang-migrate`로 migration을 실행한다.
- `up`, `down`, `version` 명령을 처리한다.

`down`은 모든 테이블을 지우지 않고 가장 최근 migration 한 단계만 되돌린다.

---

## `migrations/000001_create_messages.up.sql`

`messages` 테이블을 만드는 첫 번째 migration이다. 메시지의 ID, 보낸 사람, 내용, 생성 시각을 저장한다.

## `migrations/000001_create_messages.down.sql`

첫 번째 migration을 되돌릴 때 `messages` 테이블을 삭제한다.

---

# 애플리케이션 조립

## `internal/application/app.go`

실행에 필요한 구성요소를 생성하고 연결하는 조립 지점이다.

```text
환경변수 로드
↓
종료 신호 Context 생성
↓
PostgreSQL 연결 및 스키마 확인
↓
Hub 실행
↓
Redis 연결 및 구독 시작
↓
Repository · WebSocket Handler · HTTP Server 생성
↓
HTTP Server 실행
```

Redis에서 받은 메시지는 이 서버 인스턴스의 Hub로 전달한다. 따라서 어느 인스턴스에 연결했는지와 상관없이 같은 채널의 메시지를 받을 수 있다.

# Config 패키지

## `internal/config/config.go`

환경변수를 읽어 `Config`를 만든다.

- HTTP 서버 주소와 허용 WebSocket Origin
- PostgreSQL 접속 정보와 Connection Pool 설정
- Redis 주소, 비밀번호, DB 번호, Pub/Sub 채널
- migration 파일 경로

로컬에서는 `.env`를 읽고, 컨테이너와 Kubernetes에서는 주입된 환경변수를 사용한다. DB 비밀번호와 숫자 범위도 이 파일에서 검증한다.

---

# Chat 패키지

## `internal/chat/client.go`

WebSocket 연결 하나를 `Client`로 관리한다.

- 서버가 검증한 사용자 이름, WebSocket 연결, 전송 Queue를 보관한다.
- `readPump()`는 Text Message를 읽어 Handler가 전달한 함수로 넘긴다.
- `writePump()`는 Queue의 메시지와 Ping을 WebSocket으로 전송한다.
- 메시지 크기·읽기·쓰기 제한과 Pong 처리로 끊긴 연결을 정리한다.

## `internal/chat/hub.go`

현재 서버 인스턴스에 연결된 Client를 한 Goroutine에서 관리한다.

- Client 등록·해제
- 전체 Broadcast와 특정 Client에게 보내는 Direct Message
- 현재 연결 수 관리
- 전송 Queue가 가득 찬 느린 Client 제거
- Context 취소 시 모든 연결 종료

## `internal/chat/handler.go`

`/ws` 요청을 WebSocket으로 전환하고 채팅 규칙을 적용한다.

- Origin을 검증하고 WebSocket Upgrade를 수행한다.
- 입장과 채팅 메시지의 JSON·길이·상태를 검증한다.
- 채팅 메시지를 Repository에 저장한다.
- 저장된 채팅과 입장·퇴장 알림을 Publisher에 발행한다.
- 오류는 해당 Client에게만 보낸다.

Handler는 Client 목록을 직접 수정하거나 Redis·SQL을 직접 다루지 않는다.

## `internal/chat/message.go`

채팅 메시지 모델과 메시지 타입을 정의한다.

- `Message`: 서버가 전송하는 메시지. ID와 생성 시각을 포함한다.
- `IncomingMessage`: Client가 보내는 입력 형식이다.
- `NewSystemMessage()`, `NewErrorMessage()`: 시스템·오류 메시지를 만든다.

## `internal/chat/repository.go`

메시지 저장 기능의 인터페이스를 정의한다.

```go
type MessageRepository interface {
    Save(ctx context.Context, message *Message) error
}
```

Handler는 저장소의 구체적인 구현 대신 이 인터페이스에 의존한다.

## `internal/chat/publisher.go`

여러 채팅 서버 인스턴스에 메시지를 전달하는 Publisher 인터페이스를 정의한다. 실제 실행에서는 Redis 구현체가 이 인터페이스를 만족한다.

## `internal/chat/handler_test.go`

가짜 Repository와 로컬 Hub Publisher를 사용해 WebSocket 채팅 흐름을 테스트한다.

- 입장 알림 Broadcast
- 채팅 저장과 Broadcast
- 입장 전 채팅 차단
- Client가 보낸 Sender 위조 방지

# Database 패키지

## `internal/database/database.go`

PostgreSQL 연결 Pool을 생성한다.

- 설정으로 PostgreSQL 연결 URL을 만든다.
- `sql.DB`의 최대·유휴 연결 수와 연결 수명을 설정한다.
- 제한 시간 안에 `PingContext()`를 실행해 연결 가능 여부를 확인한다.

## `internal/database/schema.go`

서버 실행 전에 `messages` 테이블이 이미 migration되었는지 확인한다. 테이블이 없으면 서버를 시작하지 않고 `go run ./cmd/migrate up` 실행을 안내한다.

이 파일은 테이블을 생성하지 않는다. 스키마 변경의 책임은 `cmd/migrate`와 `migrations/`에 있다.

## `internal/database/message_repository.go`

`chat.MessageRepository`의 PostgreSQL 구현이다.

`messages` 테이블에 메시지를 저장하고, PostgreSQL이 생성한 `id`와 `created_at`을 원래 `Message`에 채운다.

---

# Messaging 패키지

## `internal/messaging/redis.go`

Redis Pub/Sub를 이용해 서버 인스턴스 사이의 메시지를 전달한다.

- 시작 시 Redis 연결을 확인한다.
- `Publish()`는 `Message`를 JSON으로 바꿔 지정한 Redis 채널에 발행한다.
- `Subscribe()`는 채널 메시지를 계속 받아 application이 전달한 처리 함수로 넘긴다.
- 준비 상태 확인용 `Ping()`과 연결 종료용 `Close()`를 제공한다.

---

# Server 패키지

## `internal/server/server.go`

`http.Server`를 만들고 실행·종료를 관리한다.

- 주소, Router, Timeout을 설정한다.
- 서버 실행 오류를 감시한다.
- 종료 신호를 받으면 최대 10초 동안 Graceful Shutdown을 수행한다.

## `internal/server/router.go`

HTTP 경로와 Handler를 연결한다.

- `/ws`: WebSocket 채팅 연결
- `/metrics`: Prometheus 형식 메트릭
- `/health/live`: 프로세스가 실행 중인지 확인
- `/health/ready`: PostgreSQL, 스키마, Redis가 준비됐는지 확인
- `/stats`: 현재 WebSocket 연결 수를 JSON으로 반환

## `internal/server/middleware.go`

일반 HTTP 요청의 Method, Path, 처리 시간을 구조화 로그로 기록한다. 장시간 유지되는 WebSocket 연결(`/ws`)은 일반 요청 로그에서 제외한다.

## `internal/server/metrics.go`

현재 WebSocket 연결 수를 `chat_websocket_connections` Prometheus Gauge로 노출하는 `/metrics` Handler를 만든다.

## `internal/server/metrics_test.go`

`/metrics` Handler가 성공 응답, Prometheus Content-Type, 연결 수 Gauge를 올바르게 반환하는지 테스트한다.
