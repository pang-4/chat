현재 프로젝트는 PostgreSQL에 채팅을 저장하고, Redis Pub/Sub로 모든 채팅 서버 인스턴스에 메시지를 전달한다. 아래 흐름에서 `Hub`는 **현재 인스턴스에 연결된 Client만** 관리한다.

---

## 1. Migration과 서버 시작 흐름

서버를 시작하기 전에 migration 명령으로 스키마를 준비한다.

```text
go run ./cmd/migrate up
↓
migrations/*.up.sql 실행
↓
messages 테이블 생성
```

그 뒤 서버는 다음 순서로 시작한다.

```text
cmd/server/main.go
↓
Logger 생성
↓
application.Run()
↓
config.Load()
↓
종료 신호 Context 생성
↓
database.Open() → PostgreSQL 연결 확인
↓
database.CheckSchema() → messages 테이블 존재 확인
↓
chat.NewHub() → Hub.Run() Goroutine 시작
↓
messaging.NewRedis() → Redis 연결 확인
↓
Redis.Subscribe() → 수신 메시지를 로컬 Hub에 Broadcast
↓
Repository · WebSocket Handler · HTTP Server 생성
↓
HTTP Server 실행
```

PostgreSQL, 스키마, Redis 중 하나라도 준비되지 않으면 WebSocket 서버는 시작하지 않는다. 서버가 시작된 뒤에는 `/health/ready`에서도 같은 준비 상태를 확인한다.

---

## 2. WebSocket 연결 흐름

```text
Client
↓ GET /ws
HTTP Router
↓
Handler.ServeHTTP()
↓ Origin 확인
WebSocket Upgrade
↓
Client 생성
↓
writePump() Goroutine 시작
↓
Hub.Register()
↓
readPump() 실행
```

연결 하나마다 `Client` 하나가 만들어진다.

- `readPump()`: Client가 보낸 Text Message를 읽는다.
- `writePump()`: 서버가 보낼 메시지와 Ping을 WebSocket으로 전송한다.

---

## 3. Redis를 통한 전체 Broadcast 흐름

입장, 퇴장, 채팅 메시지는 Handler에서 Redis로 발행한다. Redis를 구독 중인 모든 서버 인스턴스는 받은 데이터를 각자의 Hub로 전달한다.

```text
Handler (인스턴스 A)
↓ Message
Redis.Publish()
↓ JSON
Redis 채널
├─> 인스턴스 A의 Redis.Subscribe() → Hub A
├─> 인스턴스 B의 Redis.Subscribe() → Hub B
└─> 인스턴스 C의 Redis.Subscribe() → Hub C
       ↓
각 인스턴스에 연결된 Client의 send Channel
↓
각 Client의 writePump()
↓
WebSocket 전송
```

따라서 Client가 서로 다른 서버 인스턴스에 연결되어 있어도 같은 채팅 메시지를 받는다. Redis에 발행하지 못하면 해당 Client에게만 오류를 보낸다.

---

## 4. 사용자 입장 흐름

Client가 다음 JSON을 보낸다.

```json
{
  "type": "join",
  "sender": "pang",
  "content": ""
}
```

```text
WebSocket JSON 수신
↓
readPump()
↓
Handler.handleMessage()
↓
JSON 변환 및 join 타입 확인
↓
이름 공백 제거 · 길이 검증
↓
Client에 검증된 이름 저장
↓
System Message 생성
↓
Redis.Publish()
↓
모든 인스턴스의 Redis 구독 처리
↓
각 로컬 Hub.Broadcast()
↓
연결된 모든 Client에게 전송
```

이미 입장한 Client나 잘못된 이름은 입장시키지 않고 해당 Client에만 오류를 전송한다.

---

## 5. 채팅 메시지 흐름

Client가 다음 JSON을 보낸다.

```json
{
  "type": "chat",
  "content": "안녕하세요"
}
```

```text
WebSocket JSON 수신
↓
readPump()
↓
Handler.handleMessage()
↓
입장 여부 · 메시지 길이 검증
↓
서버가 Client.Name을 Sender로 설정
↓
MessageRepository.Save()
↓
PostgreSQL INSERT
↓
id · created_at 반환
↓
Redis.Publish()
↓
각 서버 인스턴스의 Redis.Subscribe()
↓
각 로컬 Hub.Broadcast()
↓
각 Client의 writePump()
↓
WebSocket 전송
```

DB 저장이 성공한 메시지만 Redis에 발행한다. Client가 JSON에 임의의 `sender`를 넣어도 입장 때 서버에 저장한 이름만 사용하므로 다른 사용자를 사칭할 수 없다.

---

## 6. PostgreSQL 저장 흐름

```text
Handler
↓
chat.MessageRepository 인터페이스
↓
database.MessageRepository.Save()
↓
INSERT INTO messages (sender, content)
RETURNING id, created_at
↓
Message에 ID와 생성 시각 반영
↓
Handler
```

저장에 실패하면 Redis에 발행하지 않고 보낸 Client에게 오류를 전송한다. 화면에는 보였지만 DB에는 없는 메시지가 생기는 것을 막기 위해서다.

---

## 7. 로컬 Hub Broadcast 흐름

Redis 구독 처리 함수가 받은 JSON 바이트를 Hub에 전달한다.

```text
Redis Subscribe callback
↓
Hub.Broadcast(payload)
↓
broadcast Channel
↓
Hub.Run()의 select
↓
현재 인스턴스의 Client 순회
↓
각 Client의 send Channel에 payload 추가
↓
writePump()
↓
WebSocket WriteMessage()
```

`send` Queue가 가득 찬 느린 Client는 Hub에서 제거한다. 한 연결 때문에 이 인스턴스의 모든 Broadcast가 멈추는 것을 막는다.

---

## 8. 오류와 연결 종료 흐름

입력 오류는 Redis에 발행하지 않고 해당 Client에게만 보낸다.

```text
잘못된 JSON · 잘못된 입력 · 저장/발행 실패
↓
Handler.sendError()
↓
Error Message를 JSON으로 변환
↓
Hub.Send(client, payload)
↓
direct Channel
↓
해당 Client의 send Channel
↓
writePump() → WebSocket 전송
```

연결이 끊기면 Handler의 `defer`가 Client를 Hub에서 제거한다. 입장한 Client였다면 퇴장 System Message를 Redis에 발행하여 모든 인스턴스에 알린다.

---

## 9. 연결 유지와 서버 종료

`writePump()`는 주기적으로 Ping을 보내고, Pong을 받으면 `readPump()`의 읽기 제한 시간을 갱신한다. 응답이 없거나 읽기·쓰기가 실패한 연결은 종료된다.

```text
SIGINT 또는 SIGTERM
↓
Context 취소
├─ Hub.Run() 종료 → 로컬 Client 연결 정리
└─ Server.Run() → HTTP Graceful Shutdown
↓
Redis 연결 종료
↓
PostgreSQL 연결 종료
```

---

## 전체 핵심 흐름

```text
Client
↓ WebSocket JSON
Handler
├─ 채팅: PostgreSQL 저장
└─ 입장·퇴장·채팅: Redis 발행
                         ↓
                    모든 서버 인스턴스의 구독
                         ↓
                    각 인스턴스의 Hub
                         ↓
                    연결된 Client에게 WebSocket 전송
```
