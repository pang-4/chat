## Helm이란

Helm은 Kubernetes 자원을 하나의 패키지(Chart)로 정의하고, 값(Values)을 주입해 배포하는 Kubernetes Package Manager다.

```text
여러 개의 개별 YAML 파일
              ↓
   Helm Chart로 하나의 배포 단위로 묶음
              ↓
   values.yaml로 환경별 값만 교체
              ↓
Kubernetes Manifest 완성 후 Cluster에 적용
```

Helm이 Docker Image를 만들거나 Application 코드를 실행하는 것은 아니다.

Helm의 핵심 역할은 Kubernetes YAML을 Template화하고, 값을 주입해 최종 Manifest를 만들어 Cluster에 적용하는 것이다.

---

## raw YAML 방식의 한계

Helm을 적용하기 전 이 프로젝트는 `k8s/` 폴더에 11개 YAML 파일을 직접 관리했다.

```text
k8s/
├── chat-deployment.yaml   (image tag, replica, resource가 파일에 직접 기록됨)
├── chat-service.yaml
├── chat-hpa.yaml
├── chat-ingress.yaml
├── chat-servicemonitor.yaml
├── migration-job.yaml
├── postgres-*.yaml
└── redis-*.yaml
```

이 방식에서 반복된 문제:

- Image Tag, Resource 값, HPA 임계치 같은 값이 여러 파일에 흩어져 하드코딩됨
- 값 하나를 바꾸려면 해당 YAML 파일을 직접 찾아 수정해야 함
- 운영 환경을 여러 개로 나누려면(dev, staging, prod) YAML 세트 전체를 복제해야 함
- 배포된 값의 이력을 Kubernetes 자체는 따로 기록하지 않음(Git Log로만 추적 가능)

Helm은 이 중 값과 Template을 분리하는 문제를 해결한다.

## Chart, Release, Values

| 용어 | 의미 |
|---|---|
| Chart | 배포 가능한 Kubernetes 자원 묶음. `Chart.yaml`, `templates/`, `values.yaml`로 구성 |
| Release | 특정 Cluster·Namespace에 설치된 Chart의 실행 인스턴스. 설치할 때마다 Revision이 남음 |
| Values | Chart Template에 주입되는 실제 값. `values.yaml` 또는 `--set`으로 전달 |
| Template | `{{ }}` 문법이 포함된 Kubernetes YAML 원본. Values가 채워지며 최종 Manifest가 됨 |

```text
Chart(templates/ + values.yaml)
         ↓ helm install/template
     완성된 Kubernetes Manifest
         ↓
        Release
```

같은 Chart라도 `values.yaml`만 다르게 주면 서로 다른 환경에 재사용할 수 있다.

## Helm Chart 기본 구조

```text
helm/chat/
├── Chart.yaml          # Chart 이름, 버전 정보
├── values.yaml          # 기본 값
└── templates/
    ├── _helpers.tpl      # 여러 Template에서 재사용하는 조각
    ├── chat-deployment.yaml
    ├── chat-service.yaml
    └── ...
```

- `Chart.yaml`은 Chart의 이름과 버전을 정의하는 메타데이터 파일이다.
- `values.yaml`은 Template에 채워질 기본값을 담는다.
- `templates/`의 파일은 일반 Kubernetes YAML에 Go Template 문법을 섞은 형태다.

## Helm Template 문법 핵심

| 문법 | 의미 |
|---|---|
| `{{ .Values.chat.image.tag }}` | `values.yaml`에 정의한 값을 참조 |
| `{{ .Release.Namespace }}` | 배포 대상 Namespace (설치 시점에 결정) |
| `{{ .Release.Name }}` | Release 이름 |
| `{{- if .Values.ingress.enabled }} ... {{- end }}` | 값에 따라 자원 생성 여부를 조건부로 결정 |
| `{{ include "chat.labels" . }}` | `_helpers.tpl`에 정의한 재사용 Template 호출 |
| `{{- toYaml .Values.chat.resources | nindent 12 }}` | 객체 값을 YAML 블록으로 들여쓰기 삽입 |

예:

```yaml
containers:
  - name: chat-app
    image: "{{ .Values.chat.image.repository }}:{{ .Values.chat.image.tag }}"
```

```yaml
# values.yaml
chat:
  image:
    repository: ghcr.io/pang-4/chat-app
    tag: beae0a2c701bb1644f20a40df4912ae2ae9ffb4b
```

두 파일이 합쳐지면 다음 결과가 만들어진다.

```yaml
image: "ghcr.io/pang-4/chat-app:beae0a2c701bb1644f20a40df4912ae2ae9ffb4b"
```

## helm install / upgrade / template / lint

| 명령 | 역할 |
|---|---|
| `helm install <release> <chart>` | Chart를 새 Release로 설치 |
| `helm upgrade <release> <chart>` | 이미 설치된 Release를 새 값·버전으로 갱신 |
| `helm template <chart>` | 실제로 설치하지 않고 최종 Manifest만 렌더링해서 확인 |
| `helm lint <chart>` | Chart 문법과 필수 필드 오류를 사전 점검 |
| `helm rollback <release> <revision>` | 이전 Revision으로 되돌림 |

`helm template`과 `helm lint`는 Cluster에 아무 것도 적용하지 않으므로, Commit 전에 Chart가 의도한 대로 렌더링되는지 안전하게 확인할 수 있다.

## Helm과 ArgoCD의 관계

ArgoCD는 Git 저장소의 경로가 `Chart.yaml`을 포함한 Helm Chart인지 자동으로 인식한다.

```text
ArgoCD Application.spec.source.path가 Helm Chart 경로면
        ↓
ArgoCD가 내부적으로 helm template 실행
        ↓
렌더링된 Kubernetes Manifest 확보
        ↓
Cluster의 실제 상태와 비교(Synced / OutOfSync)
        ↓
차이가 있으면 동기화
```

이 흐름에서 사람이 직접 `helm install`이나 `helm upgrade`를 실행할 필요는 없다.

Helm은 Manifest를 만드는 역할, ArgoCD는 Git과 Cluster의 상태를 비교하고 적용하는 역할을 각각 담당한다. [[00. ArgoCD란 무엇이고 GitOps는 무엇인가]]

## Helm이 하지 않는 일

- Docker Image Build와 Registry Push (GitHub Actions와 GHCR이 담당)
- Git 변경 감지와 지속적인 자동 동기화 (ArgoCD가 담당, Helm CLI 자체는 실행한 순간만 적용)
- Application 내부 로직 실행이나 오류 수정
- Cluster Node 장애 복구

Helm의 역할은 값과 Template을 조합해 올바른 Kubernetes Manifest를 만드는 것으로 한정된다.

## 핵심 정리

```text
Helm은 Kubernetes 자원을 Chart라는 재사용 가능한 단위로 패키징하는 도구다.
Chart는 templates/(YAML + 문법)와 values.yaml(값)로 구성된다.
같은 Chart라도 values.yaml만 바꾸면 여러 환경에 재사용할 수 있다.
helm template과 helm lint로 실제 배포 전에 결과를 검증할 수 있다.
ArgoCD는 Helm Chart 경로를 자동 인식해 helm template 결과를 Cluster에 동기화한다.
```
