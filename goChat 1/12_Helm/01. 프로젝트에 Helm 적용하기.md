## 무엇을 바꿨는가

기존에는 `k8s/` 폴더에 11개 raw YAML 파일을 두고 ArgoCD가 그 경로를 그대로 배포했다.

이를 `helm/chat/` Helm Chart로 전환하고, `k8s/` 폴더는 삭제했다.

```text
Before:
argocd/chat-application.yaml → path: k8s (raw YAML 11개)

After:
argocd/chat-application.yaml → path: helm/chat (Helm Chart)
```

## Chart 구조

```text
helm/chat/
├── Chart.yaml
├── values.yaml
└── templates/
    ├── _helpers.tpl
    ├── chat-configmap.yaml
    ├── chat-deployment.yaml
    ├── chat-service.yaml
    ├── chat-hpa.yaml
    ├── chat-ingress.yaml
    ├── chat-servicemonitor.yaml
    ├── migration-job.yaml
    ├── postgres-pvc.yaml
    ├── postgres-service.yaml
    ├── postgres-statefulset.yaml
    ├── redis-deployment.yaml
    ├── redis-service.yaml
    └── NOTES.txt
```

기존 `k8s/namespace.yaml`은 별도 Template으로 옮기지 않았다. ArgoCD Application의 `syncOptions`에 이미 `CreateNamespace=true`가 있어서, `{{ .Release.Namespace }}`가 그대로 Chart 전체에 사용할 Namespace가 된다.

## values.yaml 설계

값을 자원 종류별로 그룹핑했다.

```yaml
chat:
  image:
    repository: ghcr.io/pang-4/chat-app
    tag: beae0a2c701bb1644f20a40df4912ae2ae9ffb4b
  config:
    DB_HOST: postgres
    REDIS_ADDR: redis:6379
    # ...
  resources:
    requests: { cpu: 100m, memory: 64Mi }
    limits: { cpu: "1", memory: 256Mi }

hpa:
  enabled: true
  minReplicas: 3
  maxReplicas: 6

ingress:
  enabled: true
  className: nginx

serviceMonitor:
  enabled: true

postgres:
  image: postgres:17
  storage: 2Gi

redis:
  image: redis:8.2.7-alpine
```

`hpa.enabled`, `ingress.enabled`, `serviceMonitor.enabled`, `migrationJob.enabled`는 각 Template의 `{{- if }}`와 연결돼 있어, 값 하나만 `false`로 바꾸면 해당 자원을 배포하지 않을 수 있다.

```yaml
{{- if .Values.ingress.enabled }}
apiVersion: networking.k8s.io/v1
kind: Ingress
...
{{- end }}
```

## postgres-secret 처리

`postgres-secret`은 Git에 값을 커밋하지 않는 기존 방식을 그대로 유지했다. [[03. PostgreSQL Kubernetes 배포]]

```bash
kubectl create secret generic postgres-secret -n chat \
  --from-literal=DB_USER=<db-user> \
  --from-literal=DB_PASSWORD=<db-password> \
  --from-literal=DB_NAME=<db-name>
```

Chart에는 Secret 이름만 `values.yaml`의 `secret.name`으로 참조하도록 두고, Secret 자원 자체는 Template으로 만들지 않았다. 실제 비밀번호 값을 Chart에 포함하면 Helm Release 정보(`helm get values`, Secret 형태로 저장되는 Release 이력)를 통해 노출될 위험이 있기 때문이다.

## ArgoCD Application 변경

`argocd/chat-application.yaml`의 `source.path`만 바꾸면 ArgoCD가 나머지를 자동으로 처리한다.

```yaml
# Before
spec:
  source:
    repoURL: https://github.com/pang-4/chat.git
    targetRevision: main
    path: k8s

# After
spec:
  source:
    repoURL: https://github.com/pang-4/chat.git
    targetRevision: main
    path: helm/chat
    helm:
      releaseName: chat
```

`destination`, `syncPolicy`(automated, prune, selfHeal, PreSync 등)는 그대로 유지했다. ArgoCD 입장에서는 Git 경로가 Helm Chart인지만 감지가 바뀔 뿐, 자동 동기화·Prune·Self Heal 동작 방식은 동일하다.

## CI/CD 변경: Image Tag 갱신 대상

GitHub Actions의 `update-manifest` Job은 원래 `sed`로 `k8s/chat-deployment.yaml`, `k8s/migration-job.yaml`의 `image:` 줄을 직접 고쳤다. Helm 전환 후에는 `values.yaml`의 `tag:` 값 하나만 고치면 Deployment와 Migration Job 양쪽에 동시에 반영된다.

```yaml
# Before
sed -i -E \
  "s#image: ghcr.io/pang-4/chat-app:[^[:space:]]+#image: ${IMAGE_NAME}:${GITHUB_SHA}#" \
  k8s/chat-deployment.yaml \
  k8s/migration-job.yaml

# After
sed -i -E \
  "s#^(\s*tag:) .+#\1 ${GITHUB_SHA}#" \
  helm/chat/values.yaml
```

두 Template(`chat-deployment.yaml`, `migration-job.yaml`) 모두 `{{ .Values.chat.image.tag }}`를 참조하므로, 값 하나를 고치는 것으로 두 자원의 Image Tag가 함께 갱신된다.

## 배포 전 검증 명령

Cluster에 실제로 적용하기 전에 로컬에서 확인할 수 있다.

```bash
# Chart 문법·필수 필드 점검
helm lint helm/chat

# 실제 배포될 Manifest 미리 확인
helm template chat helm/chat --namespace chat
```

`helm template` 결과에는 원래 `k8s/`에 있던 자원과 같은 11종(ConfigMap, Deployment 2개, HPA, Ingress, Job, PVC, Service 3개, ServiceMonitor, StatefulSet)이 그대로 렌더링된다. Namespace는 Template이 아니라 ArgoCD의 `CreateNamespace=true`와 `helm template` 실행 시 지정한 `--namespace` 값으로 결정된다.

## 전환 전후 비교

| 항목 | Before (raw YAML) | After (Helm) |
|---|---|---|
| 값 위치 | 각 YAML 파일에 하드코딩 | `values.yaml` 한 곳에 모음 |
| Image Tag 갱신 | 파일 2개를 `sed`로 직접 수정 | `values.yaml` 한 줄만 수정 |
| 환경별 재사용 | YAML 세트 전체 복제 필요 | 다른 `values.yaml`만 지정하면 재사용 가능 |
| 배포 전 검증 | `kubectl apply --dry-run`으로 파일별 확인 | `helm lint`, `helm template`로 Chart 단위 확인 |
| ArgoCD 연동 | `path: k8s` | `path: helm/chat`, 나머지 syncPolicy는 동일 |

## 핵심 정리

```text
k8s/ raw YAML 11개를 helm/chat/ Helm Chart로 전환했다.
값은 values.yaml 한 곳에 모으고, Template은 {{ .Values.* }}로 값을 주입받는다.
postgres-secret은 이전과 동일하게 Git에 커밋하지 않고 수동으로 생성한다.
ArgoCD Application은 source.path만 helm/chat으로 바꿨고 나머지 syncPolicy는 그대로다.
GitHub Actions의 Image Tag 갱신 대상도 raw YAML 2개에서 values.yaml 한 곳으로 줄었다.
```
