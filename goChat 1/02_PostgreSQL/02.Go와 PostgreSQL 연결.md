## 목표
Go 프로그램과 PostgreSQL을 연결하여 정상적으로 통신할 수 있도록 만든다.
이번 단계에서는 데이터를 저장하지 않고,DB 연결이 정상적으로 되는지만 확인한다.

```
Go Program
↓
database.Connect()
↓
.env 읽기
↓
DSN 생성
↓
sql.Open()
↓
db.Ping()
↓
Connected to PostgreSQL!
```

# database.go
database.go는 프로젝트에서 PostgreSQL 연결을 담당하는 파일이다.
앞으로- 테이블 생성- INSERT- SELECT모두 이 연결을 사용한다.

---
# .env 읽기
```
gogodotenv.Load()
```
Go는 `.env`를 자동으로 읽지 않는다.
`godotenv`가
```
.env
↓
환경변수 등록
```
을 수행한다.

이후
```
goos.Getenv()
```
를 사용할 수 있다.

---
# DSN 생성
```go
dsn := fmt.Sprintf(...)
```
DSN(Data Source Name)DB 접속 정보를 하나의 문자열로 만든 것이다.

예시```
```
host=localhost
port=5432
user=postgres
password=postgres
dbname=chat
sslmode=disable
```

---
# sql.Open()
```go
db, err := sql.Open("pgx", dsn)
```
많이 헷갈리는 부분이다.

sql.Open()은 실제 DB에 연결하지 않는다.
하는 일- Driver 선택- DSN 저장- sql.DB 객체 생성즉
```
Go
↓
sql.DB 객체 생성
↓
아직 PostgreSQL 연결 X
```

---
# db.Ping()
```go
err = db.Ping()
```
여기서 실제 PostgreSQL에 연결한다.
```
Go
↓
PostgreSQL
↓
연결 성공
↓
Connected to PostgreSQL!
```

# sql.DB
```go
db
```
안에는- Connection Pool- Query- Exec등이 들어있는 객체이다.
앞으로 모든 SQL 작업은 이 객체를 사용한다.

# Blank Import
```go
_ "github.com/jackc/pgx/v5/stdlib"
```
Blank Import는 패키지를 사용하기 위한 것이 아니라패키지의```init()```를 실행하기 위해 사용한다.

pgx는 프로그램 시작 시
```
sql.Register("pgx")
```
를 자동으로 실행하여Go에게
```
pgx Driver
```
를 등록한다.

그래서
```go
sql.Open("pgx", dsn)
```
가 동작할 수 있다.

```go
db, err := database.Connect()

	log.Fatal(err)

3. 프로그램 종료 시 DB 연결 종료를 수행한다.

# Docker Compose 환경에서 PostgreSQL 연결

Go 서버를 Ubuntu 호스트에서 직접 실행할 때는 Docker가 Ubuntu에 공개한 포트를 사용한다.

```env
DB_HOST=localhost
DB_PORT=5432
```

```text
Ubuntu Go Server
↓ localhost:5432
PostgreSQL 컨테이너
```

Go 서버도 Docker 컨테이너로 실행하면 `localhost`를 사용할 수 없다.

컨테이너 내부의 `localhost`는 해당 컨테이너 자신을 의미하기 때문이다.

Docker Compose에서는 PostgreSQL 서비스 이름을 주소로 사용한다.

```env
DB_HOST=postgres
DB_PORT=5432
```

```text
chat-app 컨테이너
↓ postgres:5432
chat-postgres 컨테이너
```

Compose가 두 컨테이너를 같은 네트워크에 넣고 `postgres`라는 서비스 이름을 실제 컨테이너 주소로 연결한다.
