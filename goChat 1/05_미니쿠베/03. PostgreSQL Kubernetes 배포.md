## 배포 순서

PostgreSQL Pod부터 바로 만들지 않고, Pod가 사용할 자원을 먼저 준비하였다.

```text
Namespace 생성
→ Secret 생성
→ PVC 생성
→ Service 생성
→ StatefulSet 생성
→ PostgreSQL Pod 실행
```

현재 구성:

```text
Minikube Cluster
└── chat Namespace
    ├── Secret: postgres-secret
    ├── PVC: postgres-data
    ├── Service: postgres
    ├── StatefulSet: postgres
    └── Pod: postgres-0
```

---

## Namespace

파일:

```text
k8s/namespace.yaml
```

적용과 확인:

```bash
kubectl apply -f k8s/namespace.yaml
kubectl get namespace chat
```

`chat Active`가 나오면 정상이다.

## Secret

Secret은 PostgreSQL과 채팅 서버가 사용할 DB 접속 정보를 보관한다.

비밀번호가 Shell History에 직접 남지 않도록 화면에 표시하지 않고 입력하였다.

```bash
read -s -p "DB 비밀번호 입력: " DB_PASSWORD
echo
```

```bash
kubectl create secret generic postgres-secret \
  --namespace chat \
  --from-literal=DB_USER=postgres \
  --from-literal=DB_PASSWORD="$DB_PASSWORD" \
  --from-literal=DB_NAME=chat

unset DB_PASSWORD
```

확인:

```bash
kubectl get secret -n chat
```

`Opaque`는 사용자가 정의한 일반 비밀정보 Secret 타입이며, `DATA 3`은 저장한 Key가 세 개라는 뜻이다.

Secret은 Control Plane의 etcd에 저장되고 Pod가 생성될 때 환경변수나 파일로 전달할 수 있다. Base64는 암호화가 아니므로 실제 Secret 값을 Git에 Commit하지 않는다.

## PVC

파일:

```text
k8s/postgres-pvc.yaml
```

PVC는 저장공간 자체가 아니라 PostgreSQL이 사용할 영구 저장공간 요청이다.

```text
PostgreSQL Pod
→ PVC: postgres-data
→ PV
→ Minikube의 실제 저장공간
```

적용과 확인:

```bash
kubectl apply -f k8s/postgres-pvc.yaml
kubectl get pvc -n chat
```

실습 결과:

```text
NAME            STATUS   CAPACITY   ACCESS MODES   STORAGECLASS
postgres-data   Bound    2Gi        RWO            standard
```

| 값 | 의미 |
|---|---|
| `Bound` | PVC가 실제 PV와 연결됨 |
| `2Gi` | 요청한 저장 용량 |
| `RWO` | 한 Node에서 읽고 쓰기 가능한 방식 |
| `standard` | Minikube 기본 StorageClass |

## PostgreSQL Service

파일:

```text
k8s/postgres-service.yaml
```

Pod는 교체되면 IP가 바뀔 수 있으므로 Service가 고정된 내부 접속 주소를 제공한다.

```text
채팅 서버
→ postgres:5432
→ PostgreSQL Service
→ app=postgres Label을 가진 Pod
```

적용과 확인:

```bash
kubectl apply -f k8s/postgres-service.yaml
kubectl get service -n chat
```

`ClusterIP`는 Cluster 내부에서만 접근할 수 있는 Service 타입이다. PostgreSQL을 외부 인터넷에 직접 공개하지 않는다.

## PostgreSQL StatefulSet

파일:

```text
k8s/postgres-statefulset.yaml
```

StatefulSet은 PostgreSQL처럼 데이터와 안정적인 이름이 필요한 Pod를 생성하고 관리한다.

```text
StatefulSet: postgres
└── Pod: postgres-0
    ├── postgres:17 컨테이너
    ├── postgres-secret 참조
    └── postgres-data PVC 연결
```

적용과 확인:

```bash
kubectl apply -f k8s/postgres-statefulset.yaml
kubectl get statefulset,pod -n chat
```

실습 결과:

```text
statefulset.apps/postgres   1/1
pod/postgres-0              1/1   Running   0
```

현재 `replicas: 1`은 PostgreSQL Pod를 항상 하나 유지하라는 뜻이다. 현재 설정에서 단순히 3으로 변경하면 여러 PostgreSQL 프로세스가 하나의 PVC를 사용하려 하므로 변경하지 않는다.

## Service와 Pod 연결 확인

최신 Kubernetes에서는 기존 Endpoints 대신 EndpointSlice로 확인한다.

```bash
kubectl get endpointslice -n chat \
  -l kubernetes.io/service-name=postgres
```

실습 결과:

```text
PORTS   ENDPOINTS
5432    10.244.0.3
```

Service 상세 정보에서도 확인할 수 있다.

```bash
kubectl describe service postgres -n chat
```

```text
Selector:  app=postgres
Endpoints: 10.244.0.3:5432
```

연결 구조:

```text
Service IP 10.100.94.90:5432
→ Pod IP 10.244.0.3:5432
```
