# Minikube와 kubectl 설치

## 실습 환경

```text
OS: Ubuntu Linux
CPU Architecture: x86_64
CPU: 8 cores
Memory: 약 12GiB
Minikube: v1.38.1
kubectl Client: v1.35.6
Kubernetes Server: v1.35.1
Driver: Docker
```

---

## 시스템 아키텍처 확인

```bash
uname -m
nproc
free -h
```

`x86_64`이므로 AMD64용 설치 파일을 사용하였다.

---

## Minikube 설치

AMD64 Ubuntu에서 Debian Package를 내려받아 설치하였다.

```bash
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube_latest_amd64.deb
sudo dpkg -i minikube_latest_amd64.deb
```

설치 확인:

```bash
minikube version
```

설치가 끝나면 `.deb` 파일은 설치 프로그램일 뿐이므로 삭제할 수 있다.

```bash
rm minikube_latest_amd64.deb
```

이 파일을 삭제해도 설치된 Minikube와 Cluster는 삭제되지 않는다. `minikube delete`는 Cluster 자체를 삭제하므로 구분해야 한다.

## kubectl 설치

`kubectl`은 Kubernetes API Server에 명령을 보내 Cluster 자원을 생성·조회·수정하는 CLI다.

실습에서 사용한 버전과 동일한 AMD64 바이너리를 설치하는 예시는 다음과 같다.

```bash
curl -LO https://dl.k8s.io/release/v1.35.6/bin/linux/amd64/kubectl
curl -LO https://dl.k8s.io/release/v1.35.6/bin/linux/amd64/kubectl.sha256
echo "$(cat kubectl.sha256)  kubectl" | sha256sum --check
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
rm kubectl kubectl.sha256
```

설치 확인:

```bash
kubectl version --client
```

`kubectl` Client는 Kubernetes Server와 한 Minor Version 이내로 맞추는 것이 권장된다.

## Minikube Cluster 시작

Docker Driver를 사용하고 CPU 4개와 메모리 6GiB를 할당하였다.

```bash
minikube start --driver=docker --cpus=4 --memory=6g
```

현재 구조:

```text
Ubuntu
└── Docker
    └── minikube 컨테이너
        └── 단일 Node Kubernetes Cluster
```

---

## Cluster 상태 확인

```bash
minikube status
```

정상 상태:

```text
host: Running
kubelet: Running
apiserver: Running
kubeconfig: Configured
```

```bash
kubectl cluster-info
kubectl get nodes
```

실습에서 확인한 Node:

```text
NAME       STATUS   ROLES           VERSION
minikube   Ready    control-plane   v1.35.1
```

Minikube에서는 하나의 Node가 Control Plane과 애플리케이션 Pod 실행 역할을 함께 담당한다.

## 로컬 이미지를 Minikube에 전달

Ubuntu Docker에 존재하는 채팅 서버 이미지 확인:

```bash
docker image ls chat-app:local
```

Minikube에 이미지 전달:

```bash
minikube image load chat-app:local
```

전달 확인:

```bash
minikube image ls | grep chat-app
```

확인 결과:

```text
docker.io/library/chat-app:local
```

현재는 로컬 이미지를 직접 전달하지만, 이후 CI/CD 단계에서는 GitHub Actions가 이미지를 빌드해 GHCR에 Push하고 Kubernetes가 이미지를 Pull하도록 변경한다.
