## 배포 순서

PostgreSQL을 실행한 다음 DB 테이블을 준비하고 Go 채팅 서버를 배포하였다.

```text
PostgreSQL 실행
→ Migration Job 실행
→ messages 테이블 생성
→ Chat Deployment 생성
→ Chat Service 생성
→ WebSocket 연결 확인
```

---

## Migration Job

파일:

```text
k8s/migration-job.yaml
```

Migration Job은 채팅 메시지를 저장하는 작업이 아니라, 애플리케이션이 사용할 DB 구조를 준비하는 일회성 작업이다.

```text
Migration Job 시작
→ PostgreSQL 접속
→ app/migrations의 up 파일 실행
→ messages 테이블 생성
→ 작업 완료 후 종료
```

적용:

```bash
kubectl apply -f k8s/migration-job.yaml
```

완료 대기:

```bash
kubectl wait \
  --for=condition=complete \
  job/chat-migrate \
  -n chat \
  --timeout=120s
```

상태와 로그 확인:

```bash
kubectl get job,pod -n chat
kubectl logs job/chat-migrate -n chat
```

정상 결과:

```text
job.batch/chat-migrate   Complete   1/1
migration complete      command=up
```

Job Pod가 `Completed`인 것은 오류가 아니라 정해진 작업을 성공적으로 마치고 종료했다는 뜻이다.

---

## 테이블 확인

PostgreSQL Pod 안에서 테이블 목록을 확인하였다.

```bash
kubectl exec postgres-0 -n chat -- sh -c \
  'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -c "\dt"'
```

확인된 테이블:

```text
messages
schema_migrations
```

- `messages`: 채팅 메시지 저장
- `schema_migrations`: 적용된 Migration 버전 관리

## Chat Deployment

파일:

```text
k8s/chat-deployment.yaml
```

Deployment는 상태가 없는 Go 채팅 서버 Pod를 생성하고 원하는 개수만큼 유지한다.

```text
Deployment: chat-app
└── ReplicaSet
    ├── Chat Pod 1
    ├── Chat Pod 2
    └── Chat Pod 3
```

주요 설정:

```yaml
replicas: 3
```

```yaml
readinessProbe:
  httpGet:
    path: /health/ready
    port: http
```

```yaml
livenessProbe:
  httpGet:
    path: /health/live
    port: http
```

- Readiness Probe: Pod가 요청을 받을 준비가 되었는지 확인
- Liveness Probe: 애플리케이션 프로세스가 살아 있는지 확인

적용과 확인:

```bash
kubectl apply -f k8s/chat-configmap.yaml
kubectl apply -f k8s/chat-deployment.yaml
kubectl get deployment,pod -n chat
```

## Chat Service

파일:

```text
k8s/chat-service.yaml
```

Service는 여러 Chat Pod 앞에 고정된 Cluster 내부 주소를 제공한다.

```text
WebSocket 요청
→ Service: chat-app:8080
→ app=chat-app Label을 가진 Chat Pod
```

적용과 Endpoint 확인:

```bash
kubectl apply -f k8s/chat-service.yaml

kubectl get endpointslice \
  -n chat \
  -l kubernetes.io/service-name=chat-app
```

Endpoint가 세 개라면 Service가 세 Chat Pod를 모두 찾은 것이다.

## Rollout 확인

Deployment 변경 후 Pod 교체가 끝날 때까지 기다린다.

```bash
kubectl rollout status deployment/chat-app \
  -n chat \
  --timeout=120s
```

정상 결과:

```text
deployment "chat-app" successfully rolled out
```

최근 로그:

```bash
kubectl logs \
  -n chat \
  -l app=chat-app \
  --prefix \
  --tail=30
```

## 핵심 정리

```text
Job        = 한 번 실행하고 끝나는 작업
Deployment = 계속 실행되어야 하는 Pod 관리
Service    = 교체되는 Pod에 접근할 고정 주소 제공
```
