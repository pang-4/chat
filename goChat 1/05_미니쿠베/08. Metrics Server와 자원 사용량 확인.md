## Metrics Server

Metrics Server는 Node와 Pod의 현재 CPU 및 메모리 사용량을 Kubernetes Metrics API로 제공한다.

```text
kubelet의 자원 정보
→ Metrics Server 수집
→ Metrics API 제공
→ kubectl top 및 HPA 사용
```

Prometheus처럼 장기간 데이터를 저장하고 그래프로 분석하는 모니터링 시스템은 아니다.

| 도구 | 주된 목적 |
|---|---|
| Metrics Server | 현재 CPU·메모리 조회, HPA 판단 자료 |
| Prometheus | 시계열 Metric 수집·저장·조회 |
| Grafana | Prometheus 데이터를 Dashboard로 시각화 |

---

## Minikube Addon 설치

```bash
minikube addons enable metrics-server
```

Rollout 확인:

```bash
kubectl rollout status \
  deployment/metrics-server \
  -n kube-system \
  --timeout=120s
```

---

## Node 사용량

```bash
kubectl top nodes
```

실습 결과:

```text
NAME       CPU(cores)   CPU(%)   MEMORY(bytes)   MEMORY(%)
minikube   126m         1%       840Mi           7%
```

`126m`은 CPU 0.126 Core를 의미한다.

```text
1000m = CPU 1 Core
100m  = CPU 0.1 Core
1m    = CPU 0.001 Core
```

## Chat Namespace Pod 사용량

```bash
kubectl top pods -n chat
```

50 VU k6 부하 테스트 중 확인한 예:

```text
Chat Pod 1   약 11m CPU   7Mi
Chat Pod 2   약 11m CPU   8Mi
Chat Pod 3   약 10m CPU   7Mi
PostgreSQL   약 17m CPU   119Mi
Redis        약 7m CPU    3Mi
```

2초마다 확인:

```bash
watch -n 2 kubectl top pods -n chat
```

`Ctrl+C`로 관찰을 종료한다.

## HPA와 관계

HPA는 부하에 따라 Deployment의 Pod 수를 자동 조정하는 Kubernetes 자원이다.

```text
Metrics Server가 CPU·메모리 제공
→ HPA가 목표 사용률과 비교
→ Deployment replicas 증가 또는 감소
```

Metrics Server는 HPA의 기본 자원 Metric 공급자로 사용할 수 있지만, 연결 수나 메시지 처리량 같은 애플리케이션 Metric 기반 확장은 Prometheus Adapter 등의 추가 구성이 필요하다.
