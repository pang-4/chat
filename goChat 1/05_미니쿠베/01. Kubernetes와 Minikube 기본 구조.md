## Kubernetes를 사용하는 이유

Kubernetes는 여러 컨테이너를 원하는 상태로 배포하고 관리하는 플랫폼이다.

```text
원하는 상태: 채팅 서버 Pod 3개
실제 상태:   채팅 서버 Pod 2개
                 ↓
Kubernetes가 Pod 1개를 추가해 3개로 맞춤
```

Docker가 반드시 필요한 것은 아니며, Node에는 컨테이너를 실제로 실행할 `containerd` 같은 Container Runtime이 필요하다.

---

## Cluster 구조

Cluster는 Control Plane과 하나 이상의 Node를 묶은 Kubernetes 전체 실행 환경이다.

```text
Kubernetes Cluster
├── Control Plane
│   ├── API Server
│   ├── Scheduler
│   ├── Controller Manager
│   └── etcd
│
└── Worker Node
    ├── kubelet
    ├── Container Runtime
    └── Pod
        └── Container
```

| 구성 요소 | 역할 |
|---|---|
| API Server | `kubectl`과 다른 구성 요소의 요청을 받는 중앙 입구 |
| Scheduler | 새 Pod를 실행할 Node 결정 |
| Controller Manager | 원하는 상태와 실제 상태가 같도록 관리 |
| etcd | Cluster 설정과 상태 저장 |
| kubelet | Node에서 Pod 상태 관리 |
| Container Runtime | 컨테이너를 실제로 실행 |

## Minikube 구조

Minikube는 로컬에서 학습·개발용 Kubernetes Cluster를 쉽게 만드는 도구다.

이번 프로젝트에서는 Docker Driver를 사용하였다.

```text
Ubuntu 미니 PC
└── Docker
    └── minikube 컨테이너 = Kubernetes Node
        ├── Control Plane 역할
        ├── Worker Node 역할
        └── Pod 실행
```

Minikube의 Node가 Docker 컨테이너인 것은 `--driver=docker`를 선택했기 때문이다. 일반적인 운영 Kubernetes에서는 물리 서버나 VM이 Node가 될 수 있다.

## Node, Pod, Container 관계

```text
Node
└── Pod
    └── Container
        └── 애플리케이션 프로세스
```

Pod 자체가 컨테이너는 아니다. Pod는 밀접하게 동작하는 한 개 이상의 컨테이너를 묶어 Kubernetes가 관리하는 최소 배포 단위다.

보통 애플리케이션 Pod 하나에 메인 컨테이너 하나를 실행하기 때문에 Pod와 컨테이너가 비슷하게 보일 수 있다.

## Namespace

Namespace는 같은 프로젝트나 목적의 Kubernetes 자원을 묶는 논리적인 관리 구역이다. 실제 디스크 폴더나 컨테이너는 아니지만, 처음에는 Cluster 안의 관리용 폴더로 이해할 수 있다.

```text
Kubernetes Cluster
├── chat Namespace
│   ├── Secret
│   ├── PVC
│   ├── PostgreSQL Pod
│   └── Chat Server Pod
│
└── monitoring Namespace
    ├── Prometheus
    └── Grafana
```

`kind: Namespace`는 Kubernetes가 정한 자원 종류이고, `metadata.name: chat`은 사용자가 정한 구역 이름이다.

## 이번 프로젝트의 목표 구조

```text
Minikube Cluster
└── chat Namespace
    ├── PostgreSQL StatefulSet
    │   └── postgres-0 Pod
    ├── PostgreSQL Service
    ├── PostgreSQL Secret
    ├── PostgreSQL PVC
    ├── Migration Job
    ├── Chat Server Deployment
    │   ├── Chat Pod 1
    │   ├── Chat Pod 2
    │   └── Chat Pod 3
    └── Chat Server Service
```

PostgreSQL은 데이터가 있으므로 우선 하나의 Pod로 운영하고, 상태가 없는 Go 채팅 서버를 여러 Pod로 확장한다.
