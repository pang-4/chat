## Minikube란

Minikube는 개인 컴퓨터나 개발용 서버에서 작은 Kubernetes Cluster를 쉽게 실행하도록 도와주는 도구다.

Kubernetes 자체를 대체하는 제품이 아니라, Kubernetes를 로컬 환경에 간단하게 구성하는 실행 도구다.

```text
Ubuntu Mini PC
        ↓
Minikube가 Kubernetes Cluster 생성
        ↓
Deployment, Service, Pod 등 실행
```

현재 프로젝트에서는 Ubuntu Mini PC 안에 단일 Node Kubernetes Cluster를 만들기 위해 Minikube를 사용한다.

---

## Kubernetes와 Minikube의 차이

| 구분 | Kubernetes | Minikube |
|---|---|---|
| 의미 | 컨테이너를 배포하고 관리하는 플랫폼 | 로컬에 Kubernetes Cluster를 만드는 도구 |
| 목적 | 애플리케이션의 배포·복구·확장 | 학습, 개발, 로컬 검증 |
| 규모 | 단일 Node부터 다중 Node까지 가능 | 일반적으로 단일 Node 중심 |
| 운영 환경 | 물리 서버, VM, Cloud 등 | 개인 PC, 개발 서버 |

관계:

```text
Minikube
└── Kubernetes Cluster
    ├── API Server
    ├── Scheduler
    ├── Controller
    └── Node
        └── Pod
```

Minikube 명령은 Cluster 자체를 시작하고 중지할 때 사용하고, Cluster 내부의 Kubernetes 자원은 `kubectl`로 관리한다.

```bash
# Cluster 관리
minikube start
minikube stop
minikube status

# Kubernetes 자원 관리
kubectl get pods -n chat
kubectl apply -f k8s/
kubectl logs deployment/chat-app -n chat
```

---

## 이 프로젝트에서 Minikube를 사용하는 이유

### 실제 Kubernetes 기능 학습

Docker Compose만으로는 다음 Kubernetes 기능을 직접 검증하기 어렵다.

- Deployment와 ReplicaSet
- Service 기반 내부 통신
- Ingress
- ConfigMap과 Secret
- StatefulSet과 PVC
- Rolling Update
- Health Probe
- HPA 자동 확장
- Namespace 분리

Minikube는 한 대의 Mini PC에서도 이러한 Kubernetes 자원을 실제로 실행할 수 있게 한다.

### 비용 없이 Cluster 구성

Cloud Kubernetes를 사용하면 Node와 LoadBalancer 등에 비용이 발생할 수 있다.

현재 프로젝트는 보유한 Mini PC의 CPU, Memory와 Storage를 사용하므로 학습 과정에서 Cloud 비용 없이 Cluster를 운영할 수 있다.

### 배포 흐름 검증

```text
Git Push
  ↓
GitHub Actions
  ↓
GHCR Image
  ↓
ArgoCD
  ↓
Minikube Kubernetes
  ↓
Chat Pod 배포
```

Minikube는 이 흐름에서 실제 애플리케이션이 실행되는 Kubernetes 환경이다.

## 현재 Minikube 구조

현재 프로젝트는 Docker Driver를 사용한다.

```text
Ubuntu Mini PC
└── Docker
    └── minikube Container
        ├── Kubernetes Control Plane
        ├── Kubernetes Worker Node
        └── containerd
            ├── Chat Pod
            ├── PostgreSQL Pod
            ├── Redis Pod
            ├── ArgoCD Pod
            └── Monitoring Pod
```

`minikube`라는 Docker Container가 Kubernetes Node 역할을 한다.

이 Node 하나가 Control Plane과 Worker 역할을 모두 담당한다.

```bash
kubectl get nodes -o wide
```

따라서 현재 구성은 여러 물리 서버에 장애가 분산된 운영용 고가용성 Cluster가 아니다.

---

## Driver란

Driver는 Minikube가 Kubernetes Node를 어떤 방식으로 실행할지 결정한다.

대표적인 Driver:

| Driver | Node 실행 방식 |
|---|---|
| Docker | Docker Container 안에서 Node 실행 |
| KVM | Virtual Machine으로 Node 실행 |
| VirtualBox | Virtual Machine으로 Node 실행 |
| None | Host에 Kubernetes 구성요소를 직접 설치 |

현재 사용:

```text
Driver: Docker
```

확인:

```bash
minikube profile list
```

Docker Driver를 사용하므로 Minikube IP인 `192.168.49.2`는 Docker 내부 Network 주소다. Mini PC에서는 접근할 수 있지만 다른 장비인 Mac에서는 직접 접근하기 어려울 수 있다.

## Minikube와 kubectl의 역할

```text
사용자
├── minikube 명령
│   └── Cluster 생성·시작·중지·삭제
│
└── kubectl 명령
    └── Kubernetes API Server에 자원 조회·생성·수정 요청
```

예시:

```bash
minikube start
kubectl apply -f k8s/chat-deployment.yaml
kubectl get pods -n chat
```

`minikube start`는 Cluster를 실행한다.

`kubectl apply`는 실행 중인 Cluster 안에 Deployment 같은 Kubernetes 자원을 생성하거나 변경한다.

## 주요 상태와 생명주기

### 상태 확인

```bash
minikube status
```

정상 예시:

```text
host: Running
kubelet: Running
apiserver: Running
kubeconfig: Configured
```

### 중지

```bash
minikube stop
```

Cluster 실행을 중지하지만 Cluster 설정과 저장 데이터를 의도적으로 삭제하는 명령은 아니다.

### 다시 시작

```bash
minikube start
```

중지했던 Cluster를 다시 시작한다.

### 삭제

```bash
minikube delete
```

Cluster 자체를 삭제하는 명령이다. 실습 환경과 데이터가 제거될 수 있으므로 단순 재시작 목적으로 사용하면 안 된다.

## Minikube Addon

Addon은 Minikube Cluster에 자주 사용하는 기능을 쉽게 추가하는 방법이다.

현재 프로젝트에서 사용한 예:

```bash
minikube addons enable ingress
minikube addons enable metrics-server
```

| Addon | 역할 |
|---|---|
| `ingress` | NGINX Ingress Controller 설치 |
| `metrics-server` | Pod와 Node의 CPU·Memory Metric 제공 |

상태 확인:

```bash
minikube addons list
```

Ingress는 외부 요청을 Kubernetes Service로 전달하고, Metrics Server는 `kubectl top`과 HPA의 CPU 판단에 사용된다.

## Minikube Network

현재 주요 주소:

```text
Mini PC Tailscale IP: 100.126.215.15
Minikube IP:          192.168.49.2
Ingress HTTP NodePort: 31673
```

구조:

```text
Mac
  ↓ Tailscale
Mini PC
  ↓ Docker Network
Minikube Node
  ↓ NodePort / Ingress
Kubernetes Service
  ↓
Pod
```

`ClusterIP`는 Cluster 내부에서만 사용하는 Service 주소다.

`NodePort`는 Kubernetes Node의 특정 Port를 통해 Service에 접근하게 한다.

현재 HPA 부하 테스트에서는 Mac이 Minikube 내부 IP에 직접 접근하기 어려워 Mini PC에서 `socat`으로 Tailscale 주소와 Ingress NodePort를 연결하였다.

## Minikube와 운영 Kubernetes의 차이

Minikube에서 기능이 성공했다고 해서 운영 환경의 고가용성까지 검증된 것은 아니다.

| 현재 Minikube | 일반적인 운영 Kubernetes |
|---|---|
| 단일 Node | 여러 Worker Node |
| Control Plane과 Worker가 한 Node | Control Plane과 Worker 분리 가능 |
| Mini PC 한 대에 의존 | Node 장애 분산 |
| 내부 Docker Network | 정식 LoadBalancer와 Network 구성 |
| 학습용 Storage | 외부 Storage 또는 분산 Storage |
| `socat` 임시 외부 연결 | LoadBalancer, DNS, TLS |

현재 환경에서 Pod가 여러 개여도 모두 같은 Mini PC와 같은 Minikube Node에서 실행된다.

따라서 Pod 장애 복구와 애플리케이션 수평 확장은 실습할 수 있지만, Mini PC 전체가 꺼지는 Node 장애에는 대응하지 못한다.

## 자주 사용하는 명령

```bash
# Minikube 상태
minikube status

# Kubernetes Node 확인
kubectl get nodes -o wide

# 전체 Namespace의 Pod 확인
kubectl get pods -A

# Minikube IP 확인
minikube ip

# Addon 확인
minikube addons list

# Cluster 중지와 재시작
minikube stop
minikube start
```

## 핵심 정리

```text
Kubernetes는 컨테이너를 배포하고 관리하는 플랫폼이다.
Minikube는 로컬에서 작은 Kubernetes Cluster를 만드는 도구다.
현재는 Ubuntu Mini PC에서 Docker Driver로 단일 Node Cluster를 실행한다.
Minikube는 Cluster를 관리하고 kubectl은 Cluster 내부 자원을 관리한다.
현재 환경은 Kubernetes 기능 학습과 배포 검증용이며 운영용 고가용성 Cluster는 아니다.
```
