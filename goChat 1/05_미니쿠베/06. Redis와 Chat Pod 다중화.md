# Redis와 Chat Pod 다중화

## Redis가 필요했던 이유

Go 채팅 서버의 Hub는 각 프로세스 메모리에 존재한다.

```text
Chat Pod 1의 Hub
Chat Pod 2의 Hub
Chat Pod 3의 Hub
```

Pod 1에 연결된 사용자가 보낸 메시지를 Pod 1의 Hub만 Broadcast하면 Pod 2와 Pod 3에 연결된 사용자는 메시지를 받을 수 없다.

Redis Pub/Sub을 공용 메시지 전달 통로로 추가하였다.

```text
사용자
→ Chat Pod 1
→ PostgreSQL 저장
→ Redis Channel에 Publish
→ Chat Pod 1, 2, 3이 Subscribe
→ 각 Pod의 WebSocket 사용자에게 Broadcast
```

PostgreSQL과 Redis의 역할은 다르다.

| 구성요소 | 역할 |
|---|---|
| PostgreSQL | 채팅 메시지를 영구 저장 |
| Redis Pub/Sub | 실행 중인 여러 Chat Pod에 실시간 이벤트 전달 |

## Redis Deployment와 Service

파일:

```text
k8s/redis-deployment.yaml
k8s/redis-service.yaml
```

적용:

```bash
kubectl apply -f k8s/redis-deployment.yaml
kubectl apply -f k8s/redis-service.yaml
```

Rollout과 상태 확인:

```bash
kubectl rollout status deployment/redis \
  -n chat \
  --timeout=120s

kubectl get deployment,pod -n chat -l app=redis
kubectl get service redis -n chat
```

Redis 응답 확인:

```bash
kubectl exec deployment/redis \
  -n chat \
  -- redis-cli ping
```

정상 결과:

```text
PONG
```

## Chat Pod Redis 설정

ConfigMap에 Redis 접속 정보를 저장하였다.

```yaml
REDIS_ADDR: redis:6379
REDIS_DB: "0"
REDIS_CHANNEL: chat:messages
```

`redis`는 Redis Service 이름이므로 같은 `chat` Namespace의 Chat Pod가 `redis:6379`로 접속할 수 있다.

Chat Pod 시작 로그 확인:

```bash
kubectl logs pod/<CHAT_POD_NAME> -n chat \
  | grep -E 'redis|server started|ERROR'
```

정상 로그:

```text
redis subscription started  channel=chat:messages
server started              address=:8080
```

## Chat Pod 3개 확인

```bash
kubectl get pods \
  -n chat \
  -l app=chat-app
```

```text
Chat Pod 1   1/1 Running
Chat Pod 2   1/1 Running
Chat Pod 3   1/1 Running
```

Service Endpoint 확인:

```bash
kubectl get endpointslice \
  -n chat \
  -l kubernetes.io/service-name=chat-app
```

세 Pod IP가 표시되면 Service가 세 Pod를 모두 대상으로 사용하고 있다.

## 검증 결과

각 Chat Pod를 서로 다른 로컬 포트로 연결하고 Bruno 사용자 세 명을 각각 다른 Pod에 접속시켰다.

한 사용자가 보낸 메시지가 다른 두 사용자의 Bruno 화면에도 나타나는 것을 확인하였다.

```text
Pod 1 사용자 메시지 전송
→ PostgreSQL 저장 및 ID 생성
→ Redis Publish
→ Pod 1, 2, 3 Subscribe
→ 세 사용자 모두 같은 메시지 수신
```

이 결과로 단일 Pod의 메모리 Hub에만 의존하지 않고 Redis를 통해 여러 Pod가 실시간 메시지를 공유한다는 사실을 확인하였다.
