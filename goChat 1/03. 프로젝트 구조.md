# 프로젝트 구조

현재 프로젝트는 Go 애플리케이션과 Docker 설정을 분리하고, Go 애플리케이션 내부는 역할에 따라 패키지를 나누어 구성하였다.

---

## 현재 구조

```text
chat/
├── app/                         # Go 애플리케이션
│   ├── cmd/
│   │   └── server/
│   │       └── main.go         # 프로그램 실행 진입점
│   │
│   ├── internal/
│   │   ├── application/
│   │   │   └── app.go          # 설정, DB, Hub, HTTP 서버 조립 및 실행
│   │   │
│   │   ├── chat/
│   │   │   ├── client.go       # WebSocket 클라이언트 연결 관리
│   │   │   ├── handler.go      # WebSocket 연결 및 메시지 처리
│   │   │   ├── handler_test.go # WebSocket 채팅 흐름 테스트
│   │   │   ├── hub.go          # 클라이언트 등록, 해제 및 메시지 전달
│   │   │   ├── message.go      # 메시지 구조와 생성 함수
│   │   │   └── repository.go   # 메시지 저장소 인터페이스
│   │   │
│   │   ├── config/
│   │   │   └── config.go       # 환경변수 로드 및 설정 관리
│   │   │
│   │   ├── database/
│   │   │   ├── database.go     # PostgreSQL 연결 및 연결 풀 설정
│   │   │   ├── migrate.go      # messages 테이블 생성
│   │   │   └── message_repository.go
│   │   │                       # 메시지 저장소의 PostgreSQL 구현
│   │   │
│   │   └── server/
│   │       ├── middleware.go   # HTTP 요청 로그 미들웨어
│   │       ├── router.go       # URL과 Handler 연결
│   │       └── server.go       # HTTP 서버 실행과 Graceful Shutdown
│   │
│   ├── .env.example            # 환경변수 작성 예시
│   ├── go.mod                  # Go Module 및 직접 의존성
│   └── go.sum                  # 의존성 버전 검증 정보
│
├── docker/
│   └── compose.yml             # PostgreSQL 컨테이너 구성
│
├── goChat 1/                   # 프로젝트 학습 및 진행 기록
├── .gitignore                  # Git에서 제외할 파일 설정
└── README.md                   # 프로젝트 소개 및 실행 방법
```

## 주요 디렉터리 역할

### `cmd/server`

프로그램의 실행 진입점이다.

`main.go`에서는 Logger를 생성하고 `application.Run()`을 호출한다. 구체적인 설정이나 서버 구성은 다른 패키지에 맡기고, 프로그램 시작과 종료만 담당한다.

### `internal/application`

애플리케이션에 필요한 구성요소를 조립하고 전체 실행 순서를 관리한다.

```text
환경변수 로드
↓
PostgreSQL 연결
↓
테이블 생성
↓
Hub 실행
↓
Repository와 Handler 생성
↓
HTTP 서버 실행
↓
종료 신호 수신 및 안전한 종료
```

### `internal/chat`

WebSocket 채팅 기능을 담당하는 핵심 패키지이다.

- `client.go`: WebSocket 연결 하나를 `Client`로 관리한다.
- `handler.go`: 연결을 WebSocket으로 Upgrade하고 수신한 메시지를 처리한다.
- `hub.go`: 접속한 Client를 관리하고 메시지를 전달한다.
- `message.go`: 송수신하는 메시지 형식과 생성 함수를 정의한다.
- `repository.go`: 채팅 패키지가 사용할 메시지 저장 기능을 인터페이스로 정의한다.
- `handler_test.go`: 입장, 채팅, 저장, Broadcast 흐름을 테스트한다.

### `internal/config`

`.env` 또는 운영체제 환경변수를 읽어 서버와 데이터베이스 설정을 만든다.

로컬 개발에서는 `.env`를 사용할 수 있고, 컨테이너나 Kubernetes 환경에서는 외부에서 환경변수를 주입할 수 있다.

### `internal/database`

PostgreSQL과 관련된 기능을 담당한다.

- `database.go`: PostgreSQL에 연결하고 Connection Pool을 설정한다.
- `migrate.go`: 서버 시작 시 필요한 테이블이 존재하는지 확인하고 생성한다.
- `message_repository.go`: 채팅 메시지를 PostgreSQL에 저장한다.

`chat` 패키지에는 저장소 인터페이스를 두고, `database` 패키지에는 실제 PostgreSQL 구현을 두어 채팅 로직과 데이터베이스 코드를 분리하였다.

### `internal/server`

HTTP 서버와 라우팅을 담당한다.

- `/ws`: WebSocket 채팅 연결
- `/health/live`: 애플리케이션 실행 상태 확인
- `/health/ready`: PostgreSQL 연결을 포함한 준비 상태 확인
- `/stats`: 현재 WebSocket 연결 수 확인

종료 신호를 받으면 새로운 요청을 중단하고 진행 중인 요청을 정리한 뒤 서버를 종료하는 Graceful Shutdown도 이 패키지에서 처리한다.

### `docker`

현재는 `compose.yml`을 사용하여 개발용 PostgreSQL 컨테이너를 실행한다.

Go 애플리케이션을 컨테이너화하는 `Dockerfile`은 이후 단계에서 추가한다.

## 패키지 의존 관계

```text
main
↓
application
├── config
├── database ──→ chat의 Message와 Repository 인터페이스 구현
├── chat
└── server ────→ chat의 Hub와 Handler 사용
```

`application` 패키지가 각 구성요소를 생성하고 연결한다. 이를 통해 `main.go`가 복잡해지는 것을 막고 각 패키지가 자신의 역할에 집중하도록 구성하였다.

## 추가 예정 구조

프로젝트 진행 단계에 따라 다음 디렉터리를 추가할 예정이다.

```text
chat/
├── docker/
│   ├── Dockerfile              # Go 서버 이미지 생성
│   └── compose.yml             # 로컬 컨테이너 구성
│
├── k8s/                        # Kubernetes 리소스
├── .github/
│   └── workflows/              # GitHub Actions CI
├── argocd/                     # ArgoCD Application 및 GitOps 설정
├── monitoring/                 # Prometheus와 Grafana 설정
└── loadtest/                   # k6 부하 테스트 스크립트
```

아직 구현하지 않은 디렉터리는 미리 만들지 않고, 해당 단계에 도달했을 때 필요한 파일과 함께 추가한다.

## 구조 설계 기준

- 파일을 기능이 아니라 역할과 책임을 기준으로 분리한다.
- 채팅 로직이 PostgreSQL의 세부 구현에 직접 의존하지 않도록 Repository 인터페이스를 사용한다.
- 설정, 데이터베이스, 채팅, HTTP 서버의 역할을 서로 분리한다.
- 현재 필요한 구조만 유지하고 프로젝트가 확장될 때 단계적으로 디렉터리를 추가한다.
- 애플리케이션 내부에서만 사용하는 코드는 Go의 `internal` 디렉터리 아래에 둔다.
