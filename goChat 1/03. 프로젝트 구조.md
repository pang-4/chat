## Go Application

### `cmd/server`

실시간 Chat Server의 실행 진입점이다.

```text
JSON Logger 생성
→ application.Run 호출
→ 실패 시 Process 종료
```

### `cmd/migrate`

`golang-migrate`를 이용해 SQL Migration을 실행하는 별도 CLI다.

Local에서는 직접 실행할 수 있고 Kubernetes에서는 ArgoCD PreSync Job의 Command로 사용한다.

```bash
go run ./cmd/migrate up
go run ./cmd/migrate down
go run ./cmd/migrate version
```

### `internal/application`

구성요소를 생성하고 전체 생명주기를 연결하는 Composition Root다.

```text
환경변수 Load
→ PostgreSQL 연결
→ Schema 확인
→ Hub 실행
→ Redis 연결과 Subscribe
→ Repository와 Handler 생성
→ HTTP Server 실행
→ 종료 Signal 수신
→ Graceful Shutdown
```

### `internal/chat`

WebSocket Domain과 Connection 처리를 담당한다.

| 파일 | 역할 |
|---|---|
| `client.go` | Connection, Send Queue, Read/Write Pump, Ping/Pong |
| `handler.go` | Upgrade, Origin, 입장과 Chat 검증, 저장과 Publish |
| `hub.go` | Client 등록·해제, Local Broadcast, 느린 Client 제거 |
| `message.go` | Message Type과 JSON 구조 |
| `publisher.go` | Message Publisher Interface |
| `repository.go` | Message Repository Interface |
| `handler_test.go` | WebSocket 입장·저장·Broadcast 통합 흐름 |

`chat` 패키지는 PostgreSQL이나 Redis 구현에 직접 의존하지 않고 Interface를 통해 사용한다.

### `internal/database`

| 파일 | 역할 |
|---|---|
| `database.go` | pgx Driver, PostgreSQL Connection Pool |
| `message_repository.go` | Message INSERT와 ID·생성 시간 반환 |
| `schema.go` | `messages` Table 존재 여부 확인 |

Server 시작 시 Schema가 준비되지 않았으면 실행을 중단하여 Migration 누락 상태로 Traffic을 받지 않는다.

### `internal/messaging`

Redis Pub/Sub 구현이다.

```text
Publish:
Chat Message → JSON → Redis Channel

Subscribe:
Redis Channel → JSON Payload → Local Hub Broadcast
```

모든 Chat Pod가 같은 Channel을 Subscribe하므로 Pod가 달라도 같은 Message를 받을 수 있다.

### `internal/server`

| 파일 | 역할 |
|---|---|
| `router.go` | `/ws`, Health, Stats, Metrics Route |
| `server.go` | HTTP Server와 Graceful Shutdown |
| `middleware.go` | 구조화 HTTP 요청 Log |
| `metrics.go` | Prometheus Connection Gauge |
| `metrics_test.go` | Metric 출력 검증 |

## Database Migration

`app/migrations`는 Version 기반 SQL 변경을 보관한다.

```text
000001_create_messages.up.sql
→ messages Table 생성

000001_create_messages.down.sql
→ 해당 변경 Rollback
```

Migration은 Application Server와 분리하여 실행한다.

Kubernetes 배포에서는 `migration-job.yaml`이 ArgoCD PreSync Hook으로 먼저 실행되고, 성공한 뒤 Deployment가 동기화된다.

## Docker

### `docker/Dockerfile`

Go Binary를 Build하는 단계와 실행 Image를 분리한 Multi-stage Build다.

Server와 Migration Command를 하나의 Image에 포함하여 같은 Source Version을 사용한다.

### `docker/compose.yml`

Local 환경에서 다음 Container를 구성한다.

```text
PostgreSQL Healthy → Migration 완료
Redis Healthy ───────────────┐
Migration 완료 ─────────────┤
                            ↓
                      Chat App 실행
```

PostgreSQL Port는 Host에 공개하지 않고 Compose 내부 Network에서만 사용한다.

## Kubernetes

### Chat Application

| Manifest | 역할 |
|---|---|
| `chat-configmap.yaml` | Server, DB, Redis 일반 설정 |
| `chat-deployment.yaml` | Chat Container, Probe, Resource |
| `chat-service.yaml` | Pod 내부 Load Balancing |
| `chat-ingress.yaml` | WebSocket 외부 진입점 |
| `chat-hpa.yaml` | CPU 70%, Pod 3~6 자동 조절 |
| `chat-servicemonitor.yaml` | Prometheus `/metrics` 수집 |

Secret 값은 Repository에 저장하지 않고 Cluster에 별도로 생성한다.

### PostgreSQL

| Manifest | 역할 |
|---|---|
| `postgres-statefulset.yaml` | 상태 저장 DB Workload |
| `postgres-service.yaml` | Cluster 내부 5432 연결 |
| `postgres-pvc.yaml` | 2Gi 영구 Volume 요청 |

### Redis

| Manifest | 역할 |
|---|---|
| `redis-deployment.yaml` | 비영속 Pub/Sub Redis |
| `redis-service.yaml` | Cluster 내부 6379 연결 |

현재 Redis는 실시간 Event 전달용이므로 AOF와 Snapshot을 사용하지 않는다. Message 영속 저장은 PostgreSQL이 담당한다.

### Migration

`migration-job.yaml`은 새 Application 배포 전에 Schema를 준비하는 ArgoCD PreSync Hook이다.

## CI/CD

### `.github/workflows/ci.yml`

```text
main Push 또는 Pull Request
→ gofmt
→ go vet
→ go test -race -cover
→ Go Build
→ Docker Build

main Push
→ GHCR SHA Tag + latest Push
→ Kubernetes Image Tag 변경
→ Bot Commit과 Push
```

### `argocd/chat-application.yaml`

```text
Repository: pang-4/chat
Revision: main
Path: k8s
Destination: chat Namespace
```

Automated Sync, Prune, Self Heal과 Retry가 설정되어 있다.

## Load Test

| Script | 역할 |
|---|---|
| `websocket-smoke.js` | 최소 WebSocket 연결 확인 |
| `websocket-load.js` | Connection과 Message 송수신 검증 |
| `websocket-hpa.js` | VU를 점진적으로 연결하고 HPA 부하 유지 |

검증 Metric:

- Connection 성공률
- Message 전달 성공률
- WebSocket 연결 시간
- 자기 Message 지연
- DB ID 존재 여부
- 정상 종료와 Interrupted 수

→ 실습
→ 관찰 결과

## Package Dependency

```text
cmd/server
    ↓
application
    ├── config
    ├── database ──implements── chat.MessageRepository
    ├── messaging ─implements── chat.MessagePublisher
    ├── chat
    └── server
```

`application`만 구체적인 구현을 조립한다. Chat 로직은 Interface를 통해 Database와 Messaging 세부 구현에서 분리되어 있다.
